# 제작 노드 구축 원칙

자동 제작 노드·프롬프트·도구·완료 판정을 수정하기 전에 이 문서를 읽는다.

## 책임과 수정 능력

노드는 순서대로 분석(주제·내용 구성과 도메인 근거 확인), 초안(확정 내용 구현), 훅(도입), 폴리싱(문장), 시각 검증(최종 화면)을 담당한다.
책임은 우선 확인할 결과를 뜻한다. 모든 노드는 담당 결과를 완성하는 데 필요한 텍스트·이미지·배치와 이전 단계의 문제를 직접 수정한다. 정상적인 부분은 활용하고, 구체적인 문제와 수정 결과를 기록한다.

인터넷 조사의 범위와 근거 확인 기준은 [리서치 기준](research-guidelines.md#선택한-내용의-도메인-지식-조사)을 따른다. 분석의 확인 결과는 초안이 받는 답과 제작 계획에 반영한다.

## 프롬프트 구성

- 공통 지침에는 입력의 역할, 저장·복구 방식, 발견한 문제를 수정하고 검증하는 원칙을 둔다.
- 개별 지침에는 해당 단계가 만들어야 할 결과와 확인할 문제를 행동 중심으로 쓴다. 초안의 작업 방법을 후속 단계의 금지 조건으로 확대하지 않는다.
- 레퍼런스는 구성·흐름·정보 역할, 페르소나는 문체·말투, 공식 캐릭터 이미지는 외형, 제품 설정은 제품 사실과 CTA를 담당한다.
- 기준의 원문은 한 곳에 두고 개발 문서는 링크한다. 실행 프롬프트에는 필요한 원문을 주입하며 실행 중 저장소 문서를 다시 읽게 하지 않는다.
- 전달 데이터에는 결정, 현재 결과, 수정 근거와 미해결 문제를 둔다. 과거 작업 지시는 현재의 새 규칙으로 취급하지 않는다.

## 도구와 결과

모든 노드가 편집·미리보기·이미지 생성과 가져오기·공식 이미지·페르소나를 사용할 수 있다. 연결된 작업만 수정하는 경계, 실행 취소, revision, 저장 무결성과 사용자 지정 원본 조건은 유지한다. 출처 선택 정책은 요청 방식으로 구분하며 노드 이름으로 수정 종류를 차단하지 않는다.

문제 발견 → 직접 수정 → 영향 확인 → 결과 저장 순서로 진행한다. 도구 오류는 가능한 경우 요청을 고쳐 해결한다. 실제로 해결하지 못한 문제만 실패로 보고하며 문제·시도한 수정·필요한 입력을 남긴다. 모델이 실패를 보고한 결과를 자동 승인하지 않는다.

모든 제작·검토 단계는 수정 후의 완전한 요약을 반환한다. 서버는 저장 문서에서 실제 문구를 구성하며 이미지 설명·캡션도 최신 결과를 사용한다. 최종 시각 검증은 마지막 수정 revision의 전체 슬라이드 확인을 증명한다.

## 변경 시 확인 경로

`stagePrompt`의 공통·단계 문서·시작 요청·페르소나·제품·캐릭터·리서치 입력과 출력 스키마를 함께 확인한다. 이어서 `stagePolicy`, 작업 전용 MCP 경로, 도구 핸들러, runner, 저장소의 완료 판정과 후속 요약을 추적한다.

테스트는 시각 단계의 이미지 교체, 훅/폴리싱의 관련 수정, 모든 단계의 참조 전달, 최신 저장본 검증, 취소와 다른 프로젝트 접근 차단을 확인한다. 기존 금지 규칙을 정답으로 둔 테스트·AGENTS·제작 가이드·시스템 설명도 함께 갱신한다. 정적 검증과 실제 생성 검증을 구분해서 보고한다.

## 최종 출력 자동 복구

CLI JSON·출력 스키마·단계 결과 계약 오류는 저장 완료 판정 전에 최대 2회 자동 수정한다.
이전 출력과 필드별 오류를 도구 없는 별도 CLI에 전달하며 수정 결과를 같은 기준으로 재검증한다.
이 호출에는 MCP·웹·쉘·이미지 생성과 실행 토큰을 전달하지 않는다. 실제 문서 작업과 이미지 생성을 반복하지 않는다.
출처는 실제 ID 또는 URL이 필요하며 식별할 수 없는 항목은 제거한다. 식별자를 만들어 채우지 않는다.
외부 수집·인증·프로세스 실패·DB 장애·내용 검토 실패는 이 복구 대상이 아니다.
취소는 즉시 전파하고 2회 실패 시 마지막 출력·오류를 남긴다. 일반 편집 요청 오류는 실행 중 도구 응답을 보고 수정한다.
