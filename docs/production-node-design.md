# 제작 노드 구축 원칙

자동 제작 노드·프롬프트·도구·완료 판정을 수정하기 전에 이 문서를 읽는다.

## 책임과 수정 능력

노드는 순서대로 분석(주제·내용 구성과 도메인 근거 확인), 초안(확정 내용 구현), 훅(도입), 폴리싱(문장), 시각 검증(최종 화면)을 담당한다.
자동 요청은 개별 노드 실행 전에 배치 공통 주제 준비를 거친다. spy 후보 풀과 자체 게시글의 의미상 연결을 별도로 캐시하고, 최신 성과로 후보를 평가·배정한다. 선정 기준과 캐시 갱신 조건은 [리서치 기준](research-guidelines.md#소재와-전달-방식을-찾는-조사)을 따른다. 이 준비에는 편집·웹·이미지 생성 도구를 제공하지 않는다. 배정 결과와 내부/spy 원본 경로는 시작 입력과 함께 저장해 재개 때 유지한다. 내부 분석에는 해당 주제의 직접·간접 매칭만 전달하고 복제는 직접 매칭에서만 허용한다. 미시도는 대표 spy 원본의 저장 이미지를 사용해 빈 프로젝트에서 제작한다. 자동의 내부·spy 원본 모두 구성만 보존하고 주제·구체 내용은 바꾼다. 사용자가 원본 내용을 지정한 제작과 자동 변형의 내용 정책은 구분한다. 자동 중복 정책은 원본 경로와 별개로 유지한다.
책임은 우선 확인할 결과를 뜻한다. 모든 노드는 담당 결과를 완성하는 데 필요한 텍스트·이미지·배치와 이전 단계의 문제를 직접 수정한다. 정상적인 부분은 활용하고, 구체적인 문제와 수정 결과를 기록한다.

인터넷 조사의 범위와 근거 확인 기준은 [리서치 기준](research-guidelines.md#선택한-내용의-도메인-지식-조사)을 따른다. 분석의 확인 결과는 초안이 받는 답과 제작 계획에 반영한다.

## 프롬프트 구성

- 공통 지침에는 입력의 역할, 저장·복구 방식, 발견한 문제를 수정하고 검증하는 원칙을 둔다.
- 개별 지침에는 해당 단계가 만들어야 할 결과와 확인할 문제를 행동 중심으로 쓴다. 초안의 작업 방법을 후속 단계의 금지 조건으로 확대하지 않는다.
- 레퍼런스는 구성·흐름·정보 역할, 페르소나는 문체·말투, 공식 캐릭터 이미지는 외형, 제품 설정은 제품 사실과 CTA를 담당한다.
- 공통 서체 기준은 [typography.md](production-prompts/typography.md)를 모든 단계에, 측정 기반 레이아웃 기준은 [layout.md](production-prompts/layout.md)를 시각 단계에 주입한다. 수동 제작 가이드의 전체 내용을 자동 프롬프트에 복사하지 않는다.
- 기준의 원문은 한 곳에 두고 개발 문서는 링크한다. 실행 프롬프트에는 필요한 원문을 주입하며 실행 중 저장소 문서를 다시 읽게 하지 않는다.
- 전달 데이터에는 결정, 현재 결과, 수정 근거와 미해결 문제를 둔다. 과거 작업 지시는 현재의 새 규칙으로 취급하지 않는다.

## 도구와 결과

모든 노드가 편집·미리보기·이미지 생성과 가져오기·공식 이미지·페르소나를 사용할 수 있다. 연결된 작업만 수정하는 경계, 실행 취소, revision, 저장 무결성과 사용자 지정 원본 조건은 유지한다. 출처 선택 정책은 요청 방식으로 구분하며 노드 이름으로 수정 종류를 차단하지 않는다.

중복으로 인한 소재 재선정은 분석·초안에서 완료한다. 후속 단계에서는 기존 결과를 직접 수정하며, 재선정으로 이미 완료한 단계의 기록을 무효화하지 않는다.

문제 발견 → 직접 수정 → 영향 확인 → 결과 저장 순서로 진행한다. 도구 오류는 가능한 경우 요청을 고쳐 해결한다. 실제로 해결하지 못한 문제만 실패로 보고하며 문제·시도한 수정·필요한 입력을 남긴다. 모델이 실패를 보고한 결과를 자동 승인하지 않는다.

모든 제작·검토 단계는 수정 후의 완전한 요약을 반환한다. 서버는 저장 문서에서 실제 문구를 구성하며 이미지 설명도 최신 결과를 사용한다. 게시용 제목·캡션·태그는 최종 저장본에서 별도로 생성해 응답으로만 전달하며 제작 노드의 필수 저장 항목으로 두지 않는다. 최종 시각 검증은 마지막 수정 revision의 전체 슬라이드 미리보기와 경계 측정을 요구한다. 모델이 정한 관련 요소의 간격 조건을 서버가 측정값으로 확인한다. 기준은 [측정 기반 레이아웃 검토](production-prompts/layout.md)를 따른다.

## 변경 시 확인 경로

`stagePrompt`의 공통·단계 문서·시작 요청·페르소나·제품·캐릭터·리서치 입력과 출력 스키마를 함께 확인한다. 이어서 `stagePolicy`, 작업 전용 MCP 경로, 도구 핸들러, runner, 저장소의 완료 판정과 후속 요약을 추적한다.

테스트는 시각 단계의 이미지 교체, 훅/폴리싱의 관련 수정, 모든 단계의 참조 전달, 최신 저장본 검증, 취소와 다른 프로젝트 접근 차단을 확인한다. 기존 금지 규칙을 정답으로 둔 테스트·AGENTS·제작 가이드·시스템 설명도 함께 갱신한다. 정적 검증과 실제 생성 검증을 구분해서 보고한다.

## 같은 CLI에서 오류 수정 후 계속 진행

출력 JSON·스키마 오류, 분석 준비 미완료, 원본 구성·저장 문서·내용 검토 오류는 같은 CLI 세션에 구체적인 오류와 이전 결과를 돌려준다. 편집·미리보기·이미지 생성 도구와 실행 권한을 유지하고 저장 프로젝트에서 이어서 수정한다. 새 프로젝트를 만들거나 원본을 다시 수집하지 않는다. 수정 없이 승인 값만 바꿔 통과시키지 않는다.

노드별로 동일 세션을 최대 5회 자동으로 이어 실행하며 최종 실패는 마지막 원인과 수정 횟수를 보존한다. 외부 수집·인증·CLI 프로세스 실패와 DB 장애는 자동 작업 수정 대상이 아니며 취소는 즉시 전파한다. 세션 작업 폴더는 성공·실패·취소 때 정리한다.

모든 노드는 종료 전에 `production_validate_completion`으로 실제 완료 조건을 검사한다. 한 CLI 응답에서 최대 8회 검증하고, 해결되지 않으면 현재 결과를 반환해 같은 세션의 다음 수정 턴으로 이어간다. 통과 후에는 편집 없이 결과를 반환하고 서버가 다시 확인한다.

분석은 `readiness`로 실제 제작 가능 여부와 이유를 반환한다. 미완성 계획은 분석 완료나 초안 전환으로 처리하지 않는다. 자동으로 제안한 주제와 원본 정보 역할의 개수가 맞지 않으면 분석·초안이 `production_change_direction(cause="source_fit")`으로 새 소재·범위를 조정한다. 장수·구성·사용자 명시 조건은 유지하며 임의 항목으로 채우거나 원본 주제를 복원하지 않는다. 기존 성과를 수정된 주제의 직접 검증으로 확대하지 않는다.

## 내부 원본 포맷 보존

복제 시 서버가 원본 문서를 기존 분석 기록의 `source_format`에 고정한다. 이후 원본 편집과 모델의 draft 저장으로 이 스냅샷을 바꾸지 않는다. 이미지 생성 전 장별 계획 저장에서도 원본 장 수·순서·역할을 검사한다. 초안·훅·폴리싱·시각 검증 완료 때는 배치 ID와 요소 종류까지 검사한다. 문구·이미지 값과 가독성 보정은 허용한다. 각 장의 구체적인 의미 역할과 시각적 구성 보존은 원본 문구·구조를 전달받은 기존 내용/시각 검토에서 대조한다. 구조 검사만으로 의미 일치를 증명하지 않는다. 뱃지 복구도 같은 스냅샷을 사용한다. 이전 작업에 스냅샷이 없으면 복제 도구를 다시 호출해 확정 원본에서 확보하며 기존 초안은 유지한다.

외부 원본도 확보된 장 수를 빈 프로젝트 생성·계획 저장·각 단계 완료에서 검사한다. 자동 spy 경로에는 추가 원본 수집 도구를 제공하지 않는다. 선택 원본의 이미지는 분석 전 최초 확보하고, 초안·시각 검토에는 저장된 전체 이미지를 첨부한다. 후속 노드에서 Apify를 다시 호출하지 않는다.

## 단독 노드 실험

분석·훅·시각 노드는 [노드 실험 환경](node-experiments.md)에서 운영과 같은 실행 경로로 검증한다. DB 스냅샷에서 한 단계만 실행하고 원래 draft와 다른 단계 결과를 보존한다.
