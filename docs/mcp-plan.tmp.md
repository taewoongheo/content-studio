# Content Studio MCP 구현 임시 체크리스트

2026-10-03 작성. 브랜치: `feat/mcp`. 구현 및 검증 체크리스트. 실제 Codex 앱 연결을 제외한 기능은 SDK HTTP 클라이언트와 브라우저로 검증한다.

목표는 외부 Codex가 Content Studio의 미저장 문서를 읽고 편집하며, 앱에서 결과 확인과 되돌리기를 할 수 있게 하는 것이다. 기존 프로젝트를 재사용하거나 빈 프로젝트에서 시작한다.

## 합의한 범위

- [x] 현재 main에서 feat/mcp 브랜치 생성 및 전환
- [x] 앱 서버에 Streamable HTTP MCP 엔드포인트 `/mcp` 제공
- [x] 기존 편집 서비스와 문서 메모리, 되돌리기 기록, 화면 변경 알림 재사용
- [x] 별도 템플릿 데이터 모델 없이 프로젝트 복제로 재사용
- [x] 전체 문서를 읽고, 편집 명령 배열로 필요한 부분만 변경
- [x] 공유 요소 기본값 `common`과 해당 슬라이드 덮어쓰기 `local` 모두 제공
- [x] 기존 revision 검사 유지. 자동 병합이나 별도 충돌 관리 시스템은 추가하지 않음

## 시작할 프로젝트 지정

다음 계약을 구현했다. 새 콘텐츠 생성과 기존 작업 이어서 편집을 구분한다.

- [x] `create_project`의 선택 입력으로 `sourceProjectId`를 제공
- [x] 원본 ID가 있으면 문서와 이미지 연결을 복제해 새 ID의 미저장 작업 생성
- [x] 원본 ID가 없으면 기존 앱 기본값으로 빈 작업 생성. 필요한 화면 비율과 슬라이드 수는 입력으로 조정 가능
- [x] 같은 ID의 미저장 작업이 존재하면 현재 편집 상태를 복제하고, 그렇지 않으면 저장된 문서를 복제한다고 도구 설명에 명시
- [x] 원본 ID가 잘못되었으면 오류 반환. 빈 프로젝트로 조용히 대체하지 않음
- [x] 사용자가 제공한 편집기 URL의 `?job=<id>`를 에이전트가 읽어 원본 ID로 전달할 수 있도록 안내
- [x] 이름만 제공된 경우 `list_projects`로 후보 조회. 후보가 여러 개면 대상 확인 후 진행
- [x] 원본을 지정하지 않은 새 제작 요청은 빈 프로젝트로 시작. 열려 있는 작업을 임의로 원본으로 선택하지 않음
- [x] 생성 결과에 새 작업 ID, revision, 편집기 URL 반환
- [x] 기존 작업을 이어서 편집할 때는 해당 작업을 읽거나 열고, 복제하지 않음

사용 예시:

- “이 프로젝트 URL을 기준으로 가슴 루틴을 새로 만들어줘” → URL에서 ID 확인 → 원본 복제
- “등 운동 루틴 프로젝트를 기준으로 새로 만들어줘” → 프로젝트 목록에서 이름 확인 → 원본 복제
- “새로 팔 루틴을 만들어줘” → 원본 없이 빈 프로젝트 생성
- “이 프로젝트의 제목을 수정해줘” → 지정된 프로젝트를 그대로 편집

## MCP 도구 계약

| 도구 | 입력과 결과 |
| --- | --- |
| `list_projects` | 저장 프로젝트와 미저장 작업의 ID, 이름, 상태를 반환. 같은 ID는 중복 표시하지 않음 |
| `open_project` | 저장된 프로젝트를 편집 상태로 열고 작업 ID와 URL 반환. 이미 열려 있으면 미저장 상태 유지 |
| `create_project` | 선택적 원본 ID, 새 이름, 빈 문서 설정을 받아 새로운 미저장 작업 생성 |
| `read_project` | 작업 ID로 전체 문서, revision, 문서가 참조하는 이미지 정보 반환 |
| `edit_project` | 작업 ID, expectedRevision, 편집 명령 배열을 받아 일괄 적용 후 결과 반환 |
| `undo_project` | 작업 ID와 expectedRevision으로 직전 편집 취소 |
| `preview_slide` | 작업 ID와 슬라이드 ID로 현재 렌더링 이미지 및 revision 반환 |

- [x] SDK의 도구 입력 스키마와 설명에 대상 ID, 좌표 단위, 지원 스타일, 적용 범위 명시
- [x] 기존 편집 명령 스키마를 가능한 한 재사용하고 중복 정의 최소화
- [x] 쓰기 결과에 새 revision, 변경 대상 ID, 생성된 요소 ID 반환
- [x] 오류에 실패한 명령과 이유를 포함하여 에이전트가 수정 후 재시도할 수 있게 함

## 편집과 로컬 이미지

에이전트가 로컬 파일을 탐색하고 이미지를 선택한다. `list_images`와 별도 `add_image` MCP 도구는 만들지 않는다. MCP는 선택한 이미지와 편집 내용을 앱에 적용하는 역할을 맡는다.

- [x] 텍스트·이미지 내용 교체, 위치·크기·스타일·이름·역할 변경 지원
- [x] 텍스트·도형·이미지 요소 생성과 배치, 복제, 삭제 지원
- [x] 슬라이드 복제·삭제·이름·순서 변경, 배경색·레이어 순서 변경 지원
- [x] 이미지 생성·교체 명령에서 `localPath`로 로컬 절대 경로를 받는 입력 추가
- [x] 앱 서버가 파일을 읽고 기존 이미지 검증·저장 로직을 통해 assetId로 변환한 뒤 문서에 적용
- [x] 기존 assetId를 재사용하는 명령도 유지
- [x] 이미지 바이트를 에이전트가 JSON에 직접 인코딩할 필요가 없도록 구현
- [x] 같은 Mac의 파일에 앱 서버가 접근 가능한 경우를 지원 범위로 명시. 접근 불가 시 구체적인 오류 반환
- [x] 이미지 준비와 명령 검증이 완료된 후 문서와 되돌리기 기록을 한 번에 갱신
- [x] 실패 시 문서 부분 적용 방지. 이미지 준비 중 생성된 임시 에셋의 정리 방식 확인
- [x] 한 명령 묶음을 한 단계로 되돌리기. 되돌릴 때 이미지 배치는 복구하되 기존 에셋은 삭제하지 않음

## 연결과 상태 공유

- [x] 요청 시점의 문서 스냅샷과 revision으로 렌더링

- [x] 편집기·ZIP 내보내기와 줄바꿈, 도형, 이미지 배치가 일치하는지 확인

## 검증 결과

- 단위 및 기존 회귀 테스트: 116개 통과
- TypeScript 검사, lint, Next.js production build 통과
- 실제 Streamable HTTP SDK 클라이언트 연결 및 7개 도구 탐색 확인
- 개발 서버에서 MCP 편집 → 열린 편집기 SSE 갱신 → 로컬 이미지 렌더링 → 1080×1350 PNG 반환 → 복제 → 되돌리기 확인
- 프로덕션 서버에서도 같은 흐름 통과. 브라우저 API가 생성한 작업을 MCP에서 읽는 반대 방향의 메모리 공유, 저장 후 open/list, PNG 내 실제 이미지 픽셀 확인
- 사용자의 기존 DB 대신 임시 DB 사용. Codex 전역 설정은 변경하지 않음
