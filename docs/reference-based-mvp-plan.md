# 레퍼런스 기반 TikTok 슬라이드쇼 MVP

## 확정 범위

- [x] 제품 구조에는 슬라이드·영상과 레퍼런스·템플릿·처음부터 생성 선택을 유지한다.
- [x] 현재 실제 생성 기능은 TikTok 슬라이드의 레퍼런스 기반 조합만 지원한다.
- [x] 레퍼런스는 링크가 아니라 순서가 있는 이미지 묶음으로 입력받는다.
- [x] 레퍼런스 이미지는 파일 선택 또는 드래그 앤 드롭으로 추가한다.
- [x] 추가한 이미지는 썸네일과 현재 순서가 보이는 목록으로 표시한다.
- [x] 레퍼런스 순서는 화살표가 아니라 드래그 앤 드롭으로 조정한다.
- [x] computer use 없이 이미지를 Codex 입력으로 직접 전달한다.
- [x] Codex app-server 프로세스 하나를 공유한다.
- [x] 콘텐츠 작업마다 thread 하나를 만들고 전체 생성 과정에서 재사용한다.
- [x] 작업 상태와 `jobId -> threadId` 연결은 서버 메모리에만 저장한다.
- [x] 서버 재시작 시 진행 중 작업이 사라지는 제약을 허용한다.
- [x] 최종 결과는 편집 가능한 콘텐츠 기획이며 이미지 렌더링·내보내기·자동 게시는 제외한다.

## 사용자 흐름

- [x] 제품 정보, 레퍼런스 이미지, 화면 비율, 슬라이드 수, 결과 언어를 입력한다.
- [x] AI가 구조·시각 언어·전개·문체·텍스트 밀도·훅 패턴을 분석한다.
- [x] 사용자가 분석 결과를 수정하고 승인한다.
- [x] AI가 인터넷 조사에 기반한 주제와 적용 전략 3개를 제안한다.
- [x] 사용자가 전략 하나를 수정하고 승인한다.
- [x] AI가 설정한 장수에 맞춰 본문 카피를 작성한다.
- [x] 사용자가 본문을 수정하고 승인한다.
- [x] AI가 본문으로 뒷받침되는 훅 후보 4개를 제안한다.
- [x] 사용자가 훅을 선택하거나 수정한다.
- [x] 최종 편집기에서 훅과 전체 슬라이드 카피를 확인하고 수정한다.

## 핵심 요구사항

- [x] 작업 상태, revision 충돌, 상위 단계 수정에 따른 하위 결과 무효화를 관리한다.
- [x] AI 제안값, 사용자 승인값, 수정 이력을 구분한다.
- [x] 레퍼런스 분석·전략·본문·훅에 strict JSON Schema와 런타임 검증을 사용한다.
- [x] 같은 작업에서 Codex turn을 동시에 두 개 실행하지 않는다.
- [x] 모든 생성 단계는 같은 thread를 사용하되 승인된 상태를 매번 명시적으로 전달한다.
- [x] 전략은 출처와 근거를 포함하며, 본문과 훅은 존재하는 근거와 슬라이드만 참조한다.
- [x] 예상 가능한 실패는 작업을 잃지 않고 재시도할 수 있다.
- [x] 브라우저에는 내부 프롬프트, 로컬 파일 경로, 다른 작업 상태를 노출하지 않는다.
