# 제작 노드 단독 실행

분석(`analysis`), 훅 검토(`hook`), 시각 검증(`visual`)을 **현재 draft에 직접 실행**한다.
앱에서 쓰는 같은 서버·DB·프로젝트·입력·프롬프트·모델·MCP·완료 검사를 사용한다.
수정 결과는 바로 저장되며 앱에서 확인한다. 복사본·별도 서버·결과 폴더를 만들지 않는다.

```sh
pnpm node:run --id DRAFT_ID --step visual
```

- 실행 중인 앱의 draft ID를 지정한다. 기본 서버는 `http://127.0.0.1:3000`이며 `--origin`으로 변경한다.
- 분석·훅도 `--step analysis`, `--step hook`으로 실행한다. 초안 제작과 영어 폴리싱은 대상에서 제외한다.
- 선택한 단계만 실행하고 종료한다. 같은 명령을 다시 실행하면 최신 저장본에서 이어서 검토한다.
- 진행 중이거나 이미 게시된 콘텐츠에는 실행하지 않는다. 훅·시각 검증은 해당 단계와 연결 프로젝트가 있어야 한다.
- 다른 단계의 기존 기록은 유지하며 자동 재실행하지 않는다. 분석 방향을 바꾸더라도 기존 슬라이드를 새로 제작하지 않는다.
- 기본 제한 시간은 1,200초이며 `--timeout`으로 1~3,600초 사이에서 지정한다. 중단 시 이미 저장된 수정은 유지한다.

시각 검증은 [측정 기반 레이아웃 기준](production-prompts/layout.md)에 따라 측정 → 수정 → 전체 미리보기를 반복한다.
수정·검토 결과는 기존 노드 기록에서 확인한다. 실험 전용 프롬프트나 별도 데이터 관리 절차는 없다.
