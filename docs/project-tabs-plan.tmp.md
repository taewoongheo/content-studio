# 프로젝트 탭 구현 계획

브랜치: `feat/project-tabs`
기준: PR #8 병합 후 main (`7c9b054`)
상태: 구현 및 검증 완료. 세부 판단은 아래 구현 결과를 참고.

## 합의한 동작

- 탭은 서버 메모리에서 열려 있는 프로젝트를 나타낸다. 프로젝트 ID당 탭은 하나다.
- 탭 목록은 앱 서버가 관리하고 대시보드와 에디터가 동일한 목록을 표시한다.
- 현재 선택한 탭과 슬라이드·요소 선택은 브라우저별 상태다.
- 저장된 프로젝트 열기: 기존 탭이 있으면 해당 탭으로 이동하고, 없으면 프로젝트를 로드해 새 탭으로 연다.
- `+`에서는 저장된 프로젝트 선택 또는 빈 프로젝트 시작을 제공한다. 선택 전에는 프로젝트 메모리를 만들지 않는다.
- MCP 생성·복제·명시적 열기는 탭을 추가한다. 외부에서 추가된 탭 때문에 사용자의 현재 화면을 바꾸지 않는다.
- 탭 사이 이동과 대시보드 이동은 작업 종료가 아니다. 문서와 프로젝트별 최근 100단계 이력을 유지한다.
- 탭 닫기는 화면의 X로 수행한다. 별도 ‘작업 종료’ 버튼과 MCP 닫기 도구는 만들지 않는다.
- 탭 닫기는 최신 문서를 저장하고 작업을 종료한다. 저장된 프로젝트를 삭제하지 않는다.
- 서버 재시작 시 열린 탭과 이력은 초기화한다. DB 프로젝트는 다시 열 수 있다.
- 앱은 로컬 단일 서버 프로세스 운영을 유지한다. 여러 브라우저에서 열었다면 한 브라우저의 닫기가 모두에 반영된다.

## 현재 구조와 필요한 변경

- `DashboardScreen`은 프로젝트 하나를 선택하고 에디터를 교체한다. 프로젝트별 전환 위치를 따로 보관하지 않는다.
- `ContentJobRegistry`는 프로젝트별 문서·revision·이력을 이미 관리하지만 정상 종료·삭제 경로와 목록 구독은 없다.
- `EditorService`는 이력을 프로젝트당 100단계로 제한한다.
- MCP 변경은 DB 저장 후 성공하지만 수동 UI 편집은 메모리 변경이다. 닫기에서 이를 저장해야 한다.
- 기존 저장 목록 SSE는 DB 저장 알림이다. 미저장 프로젝트의 열림·닫힘까지 표현하는 열린 프로젝트 목록과 구분한다.
- 저장본 재열기는 revision을 0으로 초기화한다. 이전 비동기 요청을 새 열기 세션에서 거부해야 한다.

## 1. 서버의 열린 프로젝트 수명 관리

- [x] 별도 DB 탭 테이블 없이 registry의 열린 프로젝트를 탭 목록의 원본으로 사용한다.
- [x] 목록 응답은 ID·이름·revision·savedRevision 등 가벼운 메타데이터로 구성한다. 모든 문서와 이미지 메타데이터를 복제하지 않는다.
- [x] 열기·생성·이름/저장 상태 변경·닫기 알림을 구독할 수 있게 한다. 최초 연결과 재연결에는 전체 최신 목록을 보낸다.
- [x] 이미 열린 프로젝트는 중복 생성하지 않고 기존 문서·이력을 그대로 반환한다.
- [x] 종료 시 문서·이력·프로젝트 구독자를 해제한다. 공용 DB 이미지 자산은 삭제하지 않는다.
- [x] registry transaction을 삭제까지 지원하도록 보완한다. 삭제 후 `getRecord`를 호출하는 기존 커밋 알림 처리를 수정하고 실패 시 복구한다.
- [x] 각 열기에 `tabId`를 발급한다. MCP 편집·되돌리기 및 UI 닫기 요청은 expectedTabId와 revision을 확인한다. 동일 프로젝트 재열기에서도 이전 요청이 새 세션을 수정할 수 없다.

## 2. HTTP 및 MCP 연결

- [x] `GET /api/content-jobs`: 열린 프로젝트 요약 목록 조회. SSE Accept 시 목록 이벤트 제공.
- [x] 기존 프로젝트 생성·저장 프로젝트 열기를 같은 열린 프로젝트 수명 관리로 연결한다.
- [x] `DELETE /api/content-jobs/[jobId]`: 사용자 UI의 저장 후 닫기 요청. 세션 ID와 expectedRevision을 검증한다.
- [x] 기존 로컬 요청 경계 및 오류 응답 규칙을 유지한다.
- [x] MCP 생성·복제·open 결과를 열린 목록에 알린다. 기존 7개 도구를 유지하고 닫기 도구는 추가하지 않는다.
- [x] read/edit/undo/preview는 닫힌 프로젝트를 암묵적으로 다시 열지 않는다. 명시적 open 이후 최신 상태를 읽도록 오류와 도구 설명을 정리한다.
- [x] 닫힌 저장본을 복제할 때 원본을 잠깐 registry에 로드해 불필요한 원본 탭을 만들지 않는다. 저장본을 읽어 새 프로젝트만 연다.
- [x] 로컬 이미지 파일 준비처럼 await를 포함하는 편집은 적용 시점에도 열기 세션을 재검증한다. 닫기 전 요청이 재열기 후 살아나지 않는다.
- [x] 이미 시작된 스냅샷 preview는 결과를 반환할 수 있지만, 닫힌 작업을 복원하거나 다시 등록하지 않는다.

## 3. 전역 탭 UI와 전환

- [x] 대시보드와 에디터 바깥의 공통 workspace shell에 프로젝트 탭 바를 둔다.
- [x] 탭 선택, 프로젝트 이름, 닫기, `+`를 제공한다. 대시보드도 언제든 접근할 수 있게 한다.
- [x] `+`의 시작 화면에서 프로젝트 선택 또는 빈 프로젝트 생성을 제공한다. 저장 목록의 기존 열기 버튼도 동일 경로를 사용한다.
- [x] 서버 목록을 구독하고 MCP가 만든 탭을 자동 추가하되 현재 선택은 유지한다.
- [x] 프로젝트별 마지막 슬라이드·요소·편집 옵션을 브라우저 메모리에 보관한다. 문서 스냅샷과 이력의 원본은 서버에 둔다.
- [x] 선택한 에디터 하나만 렌더링한다. 재진입 시 최신 서버 문서를 받아 선택 위치를 복원하고 삭제된 요소는 유효한 기본 선택으로 처리한다.
- [x] 전환 전에 inspector의 미전송 변경과 command queue를 flush한다. 실패하면 현재 탭을 유지한다. 단순 전환은 DB 저장을 강제하지 않는다.
- [x] `?job=` 직접 진입, URL 갱신, 브라우저 앞/뒤 이동을 동일한 열기·전환 경로로 처리한다.
- [x] 탭이 많으면 가로 스크롤을 제공하고 키보드·접근성 이름·선택 상태를 지원한다.

## 4. 닫기와 저장

- [x] 현재 탭 닫기: 입력 변경 flush → 대기 중인 UI 명령 완료 → 최신 revision으로 서버의 저장·닫기 호출.
- [x] 다른 탭 닫기는 브라우저의 오래된 스냅샷이 아닌 서버의 최신 문서를 저장한다.
- [x] 서버에서 세션·revision 확인 → 최신 문서/이미지 저장 → 메모리 해제를 하나의 동기적 트랜잭션으로 처리한다. 파일 준비가 진행 중인 요청은 종료 후 적용을 거부한다.
- [x] 저장·검증 실패 시 문서·이력·탭을 유지하고 원인을 표시한다. 성공 전에는 화면에서 탭을 제거하지 않는다.
- [x] 편집 중 revision 충돌이면 최신 상태를 반영하고 탭을 유지한다. 변경을 덮어쓰거나 조용히 버리지 않는다.
- [x] 닫힌 프로젝트의 SSE 구독을 종료하고 다른 브라우저에도 닫힘을 전달한다. EventSource가 영구 재연결하지 않게 한다.
- [x] 현재 창에서 현재 탭을 닫으면 인접 탭으로 이동하고, 남은 탭이 없으면 대시보드를 표시한다. 다른 창에서 닫힌 경우 대시보드를 표시한다. 대시보드에서 탭이 추가되어도 자동 이동하지 않는다.
- [x] 브라우저 종료·새로고침·에디터 unmount만으로 서버 탭을 닫지 않는다. 명시적 X 조작만 작업을 종료한다.

## 구현 결과와 판단

- 탭 ID(`tabId`)는 열기마다 생성하는 UUID다. 저장 프로젝트 ID(`projectId`)와 분리하여 재열기 후 이전 요청이 같은 revision으로 통과하는 문제를 막았다. MCP 편집·되돌리기의 새 필수 입력은 `expectedTabId`다.
- `+`는 새 탭 선택 다이얼로그를 열며, 선택 전에는 빈 registry 레코드를 만들지 않는다. 열린 미저장 작업과 저장 프로젝트를 합쳐 보여준다.
- URL 복원·전환은 workspace shell에 모았고 선택한 에디터 하나만 렌더링한다. 이전 화면의 선택 상태만 탭 ID별로 보관한다.
- 기존 debounce 자동 반영과 명시적 flush가 한 요청을 공유하도록 리팩토링했다. 배경색과 이미지 준비도 전환 전에 완료하도록 연결했다.
- 현재 창에서 탭을 닫으면 인접 탭을 선택한다. 다른 창의 닫힘은 화면을 대시보드로 돌려 암묵적 재열기를 방지한다.
- 서버 HMR 전역 singleton에 새로운 수명 관리 메서드가 추가되었다. 기존 개발 서버를 사용 중이라면 한 번 재시작해야 한다. 기존 문서는 먼저 저장한다.
- 단위/회귀 테스트 132개와 TypeScript·lint·빌드 및 프로덕션 MCP/브라우저 검증을 통과했다. 빠른 텍스트/배경색 전환, 슬라이드/옵션 복원, 중복 열기, 두 창 닫힘, 닫기 후 DB 복구, 이전 탭 요청 및 이미지 준비 중 재열기 요청 거부를 검증했다.
