02

제작 방식

PHASE 01

분석 및 제작 방향

이전 로그·성과·최근 콘텐츠와 좋은 레퍼런스를 살펴본다. 관찰한 결과와 추정을 구분하고, 이번에 제공할 답을 결정한다.

왜 이 콘텐츠를 만드는지, 어떤 반응을 기대하는지, 최근 콘텐츠와 무엇이 다른지 남긴다.

저장할 결과분석 결과 + 제작 방향 + 참고 자료
PHASE 02

콘텐츠 제작

방향에 맞춰 훅·본문·CTA와 시각적 구성을 만든다. 필요한 자료가 생기면 제작 중에도 추가로 조회한다.

모든 슬라이드를 이미지로 확인하고 수정한 뒤, 프로젝트와 실제 제작 내용을 저장한다.

저장할 결과편집 가능한 프로젝트 + 완성 내용 + 변경 이유
과거 게시글과 좋은 레퍼런스의 실제 이미지를 참고한다. 내용에 맞게 소재·메시지·문구·구조·배치를 함께 바꿀 수 있다.

코드가 강제하는 것

분석·방향 저장 후 제작으로 이동한다. 콘텐츠와 로그가 저장돼야 검토 대기로 전환한다. 실행 상태와 재개 지점도 보존한다.

에이전트가 판단하는 것

어떤 자료를 얼마나 볼지, 무엇을 만들지, 어떻게 표현할지, 독자에게 어떤 새로운 답을 줄지 판단한다.

03

병렬 실행

에이전트 하나가 콘텐츠 하나를 맡는다. 분석부터 제작까지 병렬로 진행하고, 제작할 때마다 다른 작업과 최근 콘텐츠를 확인한다. 게시물은 최근 24시간, 진행 중·중단·실패·검토 대기 초안은 기간과 관계없이 비교한다.

소재와 유형이 모두 겹치면 중복으로 본다. 먼저 실제 초안으로 저장된 콘텐츠를 유지하고, 나중 작업이 자신의 내용을 바꾼다. 아이디어만 적어두는 것으로 소재를 예약하지 않는다.

중복으로 판단

팔 운동 + 루틴 목록
팔 운동 + 루틴 목록

이 기준에서는 다른 콘텐츠

팔 운동 + 루틴 목록
팔 운동 + 운동 대안 비교

소재 선택 시, 초안 저장 전, 제작 완료 전에 비교한다. 동시에 저장해 중복이 생기면 먼저 저장된 초안을 기준으로 조정한다. 중단된 작업의 초안도 포함한다.

잘된 콘텐츠는 참고 근거다. 이후 콘텐츠를 같은 소재나 형식으로 제한하는 조건으로 상속하지 않는다.
04

기록과 자료

콘텐츠 하나에 로그 하나

분석 결과무엇을 관찰했고, 어떤 근거로 어떻게 해석했는가.
제작 방향무슨 답을 왜 제공하며, 어떤 반응을 기대하고, 최근 콘텐츠와 무엇이 다른가.
완성 내용실제 프로젝트와 내용, 처음 방향에서 달라진 점과 이유.
최신 성과조회·좋아요·댓글·저장·공유 수 중 제공되는 값과 실제 관측 시각.

분석과 기대는 제작 전에 남긴다. 중복 충돌로 바꾼 방향은 갱신하고 이전 선택을 남기지 않는다. 추가 조사로 수정한 내용은 이유를 기록한다.

좋은 레퍼런스는 별도로 관리

사용자가 별도로 선별해 저장한 사례를 관리한다. 외부 게시글과 자체 게시글 모두 등록할 수 있고, 자체 게시글은 복사하지 않고 기존 프로젝트·로그에 연결한다.

소재·유형어떤 소재를 어떤 유형으로 전달하는 콘텐츠인가.
참고할 부분훅·본문·시각적 표현·CTA 중 어느 부분이며, 어떤 슬라이드에 있는가.
선별 이유무엇이 좋고, 어떤 콘텐츠에 어떻게 활용할 만한가.

조회 방식은 과거 로그와 같다. 분석·제작 중 필요한 때에 에이전트가 찾아보고, 새로운 자료도 동적으로 조사한다. 조사한 후보를 모두 선별 레퍼런스로 등록하지 않는다. 여러 사례에서 필요한 부분을 조합할 수 있으며, 무엇을 어떻게 활용했는지는 이번 제작 로그에 남긴다.

레퍼런스로 선별한 이유와 실제 성과는 구분한다. 선별됐다는 사실만으로 효과가 검증된 것은 아니다.

중간 저장은 작업 전체와 단계별로 구분

작업 전체현재 단계·전체 실행 상태·로그 연결만 관리한다.
분석 draft조사 결과·출처·분석·제작 방향, 분석에서 한 일과 남은 일을 저장한다.
제작 draft추가 조사·작성 중인 내용·변경 이유, 제작에서 한 일과 남은 일을 저장한다.

분석 완료 시 확정한 분석과 방향을 로그에 기록하고 제작 draft를 만든다. 제작은 이 출력을 읽고 진행하며, 이전 조사 전체를 복사하지 않는다. 재개할 때는 현재 단계의 draft와 이전 단계의 확정 출력을 읽는다.

분석은 TEXT, 제작 방향은 소재·유형 등 개별 컬럼, 반복되는 자료 목록은 JSON으로 저장한다. 실제 슬라이드 문서·이미지는 기존 프로젝트를 사용한다. 검색 응답이나 도구 호출 전체를 저장하지 않는다.

실제 모습도 함께 참고

자체 콘텐츠기존 프로젝트의 미리보기를 필요할 때 생성한다.
외부 레퍼런스전체 슬라이드 축소본을 순서대로 DB에 저장한다.
게시 당시 모습URL 등록 시 전체 슬라이드 축소본을 보존한다. 이후 프로젝트를 수정해도 유지한다.

축소본은 우선 너비 540px의 WebP로 저장하며, 실제 글자 가독성을 확인해 압축 품질을 정한다.

Apify로 최신 성과 갱신 선택 완료

  • 공개 게시물 URL로 조회한다. 운영 TikTok 계정의 로그인·쿠키는 전달하지 않는다.
  • 시작할 때 한국 날짜 기준 오늘·어제·2일 전·3일 전 게시물을 갱신한다.
  • 게시물마다 최신 값 한 행만 덮어쓴다. 범위를 벗어나면 마지막 값을 유지한다.
  • 수집에 실패하면 이전 값을 보존하고 새 제작을 시작하지 않는다.

제공되지 않는 지표를 0으로 채우지 않는다. 게시 후 경과 시간이 다른 수치를 같은 조건처럼 비교하지 않는다. 조회·반응 수치를 앱 설치로 간주하지 않는다.

05

실행과 완료

실행 화면에서 제어

콘텐츠별 두 단계와 현재 상태를 노드·연결선으로 보여준다. 실행 중인 부분을 강조하고, 인스턴스마다 색상을 다르게 적용한다. 노드를 누르면 해당 단계 draft의 조사·작성 내용·한 일·남은 일·오류를 확인한다. DB 저장·변경이 성공할 때 해당 노드를 짧게 scale 박동시킨다.

작업마다 중단·재개와 포스트 열기를 제공한다. 제작 모델은 화면 맨 아래에서 바꿀 수 있으며 기본값은 gpt-5.6-sol이다. 포스트는 연결된 기존 편집기로 열고, 이미 열린 작업은 재사용한다.

에이전트의 제작 단계는 분석·방향과 콘텐츠 제작 두 개다. 공통 성과 갱신, 외부 검토·수정, URL 등록은 별도 처리다.

기록 갱신 → 분석·방향 → 제작 → 검토 대기 → URL 등록 → 완료

중단해도 같은 작업으로 재개

작업 전체 draft에는 현재 단계와 실행 상태를, 각 단계 draft에는 해당 조사·초안·수행한 일과 남은 일을 저장한다. 프로젝트는 로그에 연결한다. 재개하면 새 CLI 에이전트가 이 기록을 읽고 같은 작업을 이어간다. 앱 재시작으로 끊긴 실행도 재개할 수 있게 남긴다.

취소·제거하면 모든 draft 삭제

명시적으로 취소·제거하면 실행을 종료하고 상위·분석·제작 draft를 모두 삭제한다. 늦게 도착한 저장이 삭제된 작업을 복구하지 못하게 한다. 중단은 재개를 위해 draft를 보존한다.

URL 등록이 작업의 마지막 단계

직접 업로드한 뒤 URL을 등록한다. 프로그램이 실제 게시 시각과 전체 슬라이드를 가져와 저장하면 완료한다. 조회나 저장이 실패하면 같은 작업에서 다시 시도한다.

실행 화면은 실제 상태를 표시한다. 외부 데스크탑에서 직접 수정하며 피드백 저장·동기화 기능은 제외한다. 수정 이유가 자동 기록된다고 가정하지 않는다.

06

구현 범위

제작·관찰·다음 판단을
하나의 작업 흐름으로 연결한다.

이번 구현시작·성과 갱신, CLI 병렬 제작, 콘텐츠별 로그, 이미지 레퍼런스 조회, 중단·재개, 실행 화면, 포스트 열기, URL 등록과 이미지 보존.
연결 검증선택한 Apify Actor가 실제 슬라이드쇼의 필요한 지표·게시 시각·전체 이미지를 반환하는지 샘플로 확인한다. 병렬 제작에서는 저장된 초안을 기준으로 중복 조정이 작동하는지 확인한다.
추후상시 서버, 자동 예약 제작, 24h·48h·72h 성과 이력 수집.

실행 화면과 DB 연결을 구현했다. 실제 생성 전에는 선별 레퍼런스와 기존 게시 URL을 보완한다.
