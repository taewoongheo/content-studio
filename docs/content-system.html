02

제작 방식

PHASE 01

분석 및 제작 방향

게시 URL이 등록된 과거 로그·성과와 좋은 레퍼런스를 살펴본다. 미게시 작업은 중복 확인에 사용한다. 관찰한 결과와 추정을 구분하고, 이번에 제공할 답을 결정한다. 분석 자료 노드가 전달한 내부 게시글과 외부 콘텐츠 레퍼런스에서 소재 후보를 찾고, 실제 성과·제공 가치를 비교해 선택한다. 표현 방식은 과거 게시글과 필요한 외부 사례를 비교해 결정한다.

왜 이 콘텐츠를 만드는지, 어떤 반응을 기대하는지, 최근 콘텐츠와 무엇이 다른지 남긴다.

저장할 결과분석 결과 + 제작 방향 + 참고 자료
PHASE 02

초안 제작

분석에서 확정한 내부 원본을 문구·이미지와 함께 복제한다. 복제한 요소의 텍스트와 이미지를 새 내용으로 교체한다. 각 노드는 담당 결과를 위해 발견한 문제를 직접 수정한다.

모든 슬라이드를 이미지로 확인하고 수정한 뒤, 프로젝트와 초안을 저장한 뒤 훅 검토로 넘어간다.

저장할 결과편집 가능한 프로젝트 + 초안 + 변경 이유
PHASE 03

훅 검토·수정

참고 훅의 문구·실제 이미지를 보고, 현재 본문이 주는 가치가 바로 드러나는지 검토한다. 본문·주장·CTA를 유지하면서 훅 텍스트만 수정한다.

저장할 결과검토 판단 + 선택한 훅 + 수정 이유
PHASE 04

영어 폴리싱

문법·자연스러운 표현·용어·반복을 점검한다. 페르소나의 문체로 의미를 명확하게 다듬고 필요한 관련 수정을 수행한다.

저장검토 결과, 수정한 내용과 최종 전체 요약
PHASE 05

시각 검증·수정

현재 화면의 겹침·잘림·가독성·내용과 이미지의 일치 여부를 확인한다. 발견한 문제는 문구 수정이나 이미지 재생성을 포함해 직접 해결하고 최신 전체 화면을 다시 확인한다.

저장할 결과시각 검토 + 수정 내역 + 최종 검토본
과거 게시글과 좋은 레퍼런스의 실제 이미지를 참고한다. 초안은 내용을 구현하고 후속 노드는 담당 결과를 검토하며 관련 문제를 수정한다. 필요한 리서치는 각 단계 안에서 수행한다.

코드가 강제하는 것

분석 → 초안 → 훅 검토 → 영어 폴리싱 → 시각 검증을 차례로 실행한다. 모든 노드는 공통 수정·생성 도구를 사용한다. 최종 시각 검증은 마지막 저장 revision의 전체 장 미리보기를 확인한다. 검토를 통과하지 못하면 해당 단계에서 멈추고, 시각 검증까지 통과해야 완료한다. 실행 상태와 재개 지점도 보존한다.

에이전트가 판단하는 것

어떤 자료를 얼마나 볼지, 무엇을 만들지, 어떻게 표현할지, 독자에게 어떤 새로운 답을 줄지 판단한다.

03

병렬 실행

콘텐츠 하나를 독립 작업으로 만들고, 각 단계는 별도 CLI가 맡는다. 여러 콘텐츠는 병렬로 진행하되 각 콘텐츠의 다섯 단계는 순서대로 실행하고, 제작할 때마다 다른 작업과 최근 콘텐츠를 확인한다. 게시물은 최근 24시간, 진행 중·중단·실패·검토 대기 초안은 기간과 관계없이 비교한다.

소재와 유형이 모두 겹치면 중복으로 본다. 먼저 실제 초안으로 저장된 콘텐츠를 유지하고, 나중 작업이 자신의 내용을 바꾼다. 아이디어만 적어두는 것으로 소재를 예약하지 않는다.

중복으로 판단

팔 운동 + 루틴 목록
팔 운동 + 루틴 목록

이 기준에서는 다른 콘텐츠

팔 운동 + 루틴 목록
팔 운동 + 운동 대안 비교

소재 선택 시, 초안 저장 전, 제작 완료 전에 비교한다. 동시에 저장해 중복이 생기면 먼저 저장된 초안을 기준으로 조정한다. 중단된 작업의 초안도 포함한다.

잘된 콘텐츠는 참고 근거다. 이후 콘텐츠를 같은 소재나 형식으로 제한하는 조건으로 상속하지 않는다.
04

기록과 자료

콘텐츠 하나에 로그 하나

분석 결과무엇을 관찰했고, 어떤 근거로 어떻게 해석했는가.
제작 방향무슨 답을 왜 제공하며, 어떤 반응을 기대하고, 최근 콘텐츠와 무엇이 다른가.
완성 내용실제 프로젝트와 내용, 처음 방향에서 달라진 점과 이유.
최신 성과조회·좋아요·댓글·저장·공유 수 중 제공되는 값과 실제 관측 시각.

분석과 기대는 제작 전에 남긴다. 중복 충돌로 바꾼 방향은 갱신하고 이전 선택을 남기지 않는다. 추가 조사로 수정한 내용은 이유를 기록한다.

외부 레퍼런스 자료함

지정 계정의 게시글을 저장·재사용한다. 자동은 내부 원본에서 소재를 변형하고 지정 제작은 선택 원본을 활용한다. 일반 검색은 선택한 내용의 도메인 지식 확인에 사용한다.

분석은 내부 복제 원본을 확정한다. 자동은 내부 후보를 비교하고 외부 지정은 지정 원본과 필요한 내부 후보를 확인한다. 외부 후보 추가 조회는 외부 지정 초안에서 필요한 경우에만 최대 5개 허용한다. 훅의 내부 원본 문구 조회는 선택 사항이다. 초안·훅·폴리싱은 내용만 검토하고 마지막 시각 검수에서 실제 표시 결함을 검사·수정한다.

분석 및 제작 방향 단계에서만 저장된 자료가 부족하면 한 번 지정 계정 한 곳의 최근 후보를 최대 12개 수집한다. 동시 요청과 15분 이내 자동 재조회는 공유한다. 후보 수집량과 참고 3개 한도는 별도다. 제외한 게시글은 다시 수집해도 복원하지 않는다. 사용한 부분과 판단은 해당 단계에 기록한다.

내용 구성과 도메인 지식 조사

분석은 정해진 내부 후보 또는 지정 원본에서 소재를 고른다. 독자가 내용을 이해하거나 판단·실행했을 때 목적에 맞는 결과로 이어지는지 검토하고, 필요한 도메인 지식만 인터넷으로 확인한다. 근거를 반영한 답·구성·순서와 적용 조건을 초안에 전달한다. 초안은 이를 문구와 이미지로 구현하며 후속 단계도 발견한 문제에 필요한 지식을 확인할 수 있다. 조사 기준은 리서치 기준을 따른다.

분석에 가져올 과거 게시글

좋아요·댓글·저장의 합을 조회 수로 나눈 반응률 상위 10개를 먼저 가져온다. 상위 그룹을 제외하고 반응률 하위 10개를 가져온 뒤, 두 그룹을 제외하고 실제 게시일 최신 10개를 추가한다. 최대 30개이며 각 그룹은 부족하면 있는 만큼만 가져온다. 조회 수가 0이거나 필요한 성과가 없는 게시글은 상·하위 성과 순위에서 제외하지만 최근 게시글에는 포함할 수 있다. 검색어를 입력하면 해당 소재·이름에 맞는 게시글 안에서 같은 기준으로 선택한다. 외부 자료함 조회와 중복 검사는 별도다.

영어 원본과 한국어 표시

분석·제작 방향·조사 기록·참고 이유·작성 내용·최종 요약은 영어로 저장한다. 영어 작성은 지침으로 관리하며 언어 감지를 통한 저장 차단은 하지 않는다. URL·ID·수치는 번역 대상이 아니다.

캔버스 노드와 사이드바는 영어 원문을 표시한다. 제작 화면에서 단계별 내용이 조회되면 노드 클릭 없이 별도 CLI로 상세 내용을 미리 번역한다. 상세 내용은 짧은 필드와 긴 분석·조사·본문을 나눠 번역하고, 완료된 항목부터 표시한다. 번역 모델은 제작 모델과 별개로 gpt-6-luna를 사용하며 CLI는 최대 2개까지 동시에 실행한다. 같은 문장은 재사용하며 번역 캐시는 로컬 파일에 보관한다. 상세 패널을 닫아도 제작 화면의 백그라운드 번역은 유지하며, 제작 화면을 떠나 마지막 조회자가 없어지면 진행 중 번역을 중단한다. DB·다음 단계 입력·실제 슬라이드는 바꾸지 않는다. 상세 화면에서 영어 원문으로 전환할 수 있다. 번역 실패 시 원문과 오류를 표시한다.

중간 저장은 작업 전체와 단계별로 구분

작업 전체현재 단계·전체 실행 상태·로그·편집 프로젝트 연결을 관리한다.
분석 draft조사 결과·출처·분석·제작 방향, 분석에서 한 일과 남은 일을 저장한다.
제작 draft추가 조사·작성 중인 내용·변경 이유, 제작에서 한 일과 남은 일을 저장한다.

분석 완료 시 확정한 분석과 방향을 로그에 기록하고 제작 draft를 만든다. 제작은 이 출력을 읽고 진행하며, 이전 조사 전체를 복사하지 않는다. 재개할 때는 현재 단계의 draft와 이전 단계의 확정 출력을 읽는다.

분석은 TEXT, 제작 방향은 소재·포맷 등 개별 컬럼, 반복되는 자료 목록은 JSON으로 저장한다. 실제 슬라이드 문서·이미지는 기존 프로젝트를 사용한다. 검색 응답이나 도구 호출 전체를 저장하지 않는다.

실제 모습도 함께 참고

자체 콘텐츠기존 프로젝트의 미리보기를 필요할 때 생성한다.
외부 레퍼런스전체 슬라이드 축소본을 순서대로 DB에 저장한다.
게시 당시 모습URL 등록 시 전체 슬라이드 축소본을 보존한다. 이후 프로젝트를 수정해도 유지한다.

축소본은 우선 너비 540px의 WebP로 저장하며, 실제 글자 가독성을 확인해 압축 품질을 정한다.

Apify로 최신 성과 갱신 선택 완료

  • 공개 게시물 URL로 조회한다. 운영 TikTok 계정의 로그인·쿠키는 전달하지 않는다.
  • 시작할 때 한국 날짜 기준 오늘·어제·2일 전·3일 전 게시물을 갱신한다.
  • 게시물마다 최신 값 한 행만 덮어쓴다. 범위를 벗어나면 마지막 값을 유지한다.
  • 수집에 실패하면 이전 값을 보존하고 새 제작을 시작하지 않는다.

제공되지 않는 지표를 0으로 채우지 않는다. 게시 후 경과 시간이 다른 수치를 같은 조건처럼 비교하지 않는다. 조회·반응 수치를 앱 설치로 간주하지 않는다.

05

실행과 완료

실행 화면에서 제어

콘텐츠별 두 단계와 현재 상태를 노드·연결선으로 보여준다. 실행 중인 부분을 강조하고, 인스턴스마다 색상을 다르게 적용한다. 성과 갱신 노드에서는 갱신 대상·수치·조회 시각과 분석에 기록된 활용 이유를 오른쪽에서 확인한다. 노드를 누르면 해당 단계 draft의 조사·작성 내용·한 일·남은 일·오류를 확인한다. DB 저장·변경이 성공할 때 해당 노드를 짧게 scale 박동시킨다.

작업마다 중단·재개와 포스트 열기를 제공한다. 제작 모델은 gpt-6.1-sol, 화면 번역 모델은 gpt-6-luna로 고정한다. 포스트는 연결된 기존 편집기로 열고, 이미 열린 작업은 재사용한다. 참고 게시글은 DB 문서와 이미지로 조회하며 편집기 탭을 열지 않는다.

에이전트의 제작 단계는 분석·방향과 콘텐츠 제작 두 개다. 공통 성과 갱신, 외부 검토·수정, URL 등록은 별도 처리다.

기록 갱신 → 분석·방향 → 제작 → 검토 대기 → URL 등록 → 완료

중단해도 같은 작업으로 재개

작업 전체 draft에는 현재 단계와 실행 상태를, 각 단계 draft에는 해당 조사·초안·수행한 일과 남은 일을 저장한다. 프로젝트는 작업 전체 draft에 연결한다. 재개하면 새 CLI 에이전트가 이 기록을 읽고 같은 작업을 이어간다. 앱 재시작으로 끊긴 실행도 재개할 수 있게 남긴다.

취소·제거하면 모든 draft 삭제

명시적으로 취소·제거하면 실행을 종료하고 상위·분석·제작 draft와 연결 문서·이미지·미게시 로그를 모두 삭제한다. 늦게 도착한 저장이 삭제된 작업을 복구하지 못하게 한다. 중단은 재개를 위해 draft를 보존한다.

URL 등록이 작업의 마지막 단계

제작 중 문서와 이미지는 draft에 연결한다. 편집기로 열 수 있지만 대시보드 모든 콘텐츠에는 표시하지 않는다. 직접 업로드한 뒤 URL을 입력하고 게시를 누른다. 실제 게시 정보와 전체 슬라이드 저장에 성공하면 프로젝트 연결을 로그로 옮기고 모든 단계 draft를 삭제한다. 그때 대시보드에 표시된다. 실패하면 draft를 유지해 다시 시도한다. 남은 draft를 모두 게시하거나 삭제해야 새 제작을 시작할 수 있다.

실행 화면은 실제 상태를 표시한다. 외부 데스크탑에서 직접 수정하며 피드백 저장·동기화 기능은 제외한다. 수정 이유가 자동 기록된다고 가정하지 않는다.
