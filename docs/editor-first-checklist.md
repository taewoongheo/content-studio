# 레퍼런스 기반 슬라이드 편집기 전환

현재의 단계별 검토 UI를 레퍼런스 분석 직후 열리는 편집기로 전환한다. 이번 범위는 TikTok 슬라이드쇼의 레퍼런스 방식이다. 영상·템플릿·처음부터 생성 선택지는 유지하되 생성 기능은 확장하지 않는다.

## 전제

- [x] 슬라이드 전체를 JSON 문서로 관리한다. AI 결과와 사용자 수정을 같은 문서에 반영한다.
- [x] Element는 역할·의미, 시각 레이어의 위치·스타일, 채울 콘텐츠 슬롯을 포함한다.
- [x] Element 원본은 슬라이드 밖에 두고, 슬라이드마다 배치된 Element와 슬롯 값을 가진다.
- [x] 스타일 변경은 개별 수정과 공통 수정으로 구분한다.
- [x] 레퍼런스 이미지는 구조 분석의 근거다. 분리할 수 없는 배경·사진은 교체 가능한 이미지 자리로 표시한다.
- [x] 첫 범위에는 이미지 생성과 파일 내보내기를 포함하지 않는다.

## 구현 체크리스트

- [x] 1. JSON 문서, Element, 슬라이드, 개별·공통 수정 명령을 정의하고 로직 테스트로 검증한다.
- [x] 2. 레퍼런스 이미지 분석 결과가 Element 원본과 훅·본문·CTA 슬라이드 초안을 만들도록 스키마·검증·프롬프트를 전환한다.
- [x] 3. 사용자와 AI가 같은 수정 명령을 사용하도록 작업 API를 만들고 revision 충돌·동시 생성·되돌리기를 검증한다.
- [x] 4. 주제 논의·선택, 본문 슬롯 채우기, 훅 논의·선택, 자유로운 채팅 수정을 한 작업의 Codex thread로 연결한다.
- [x] 5. 편집기에서는 앱 사이드바를 숨기고 슬라이드 캔버스, 슬라이드 순서, Element 편집 탭, 채팅을 제공한다.
- [x] 6. 타입 검사·린트·빌드와 로직 테스트를 통과시킨다. UI 자동 테스트는 작성하지 않는다.

각 단계에서 테스트를 먼저 작성하고, 동작 확인 후 관련 코드를 한 번 리팩터링한다. 폴더가 다섯 파일을 넘으면 소유 경계를 검토한다.
