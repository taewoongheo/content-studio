테이블 역할과 연결

먼저 저장 책임과 단계 간 전달을 정하고, 그 안에 컬럼을 둔다. 제작용 테이블은 10개다. 이 구조로 구현했으며 기존 DB를 v18로 일회성 변환했다. 기존 자료에서 확인할 수 없는 값은 비워두었다.

단계별 저장과 전달

시점저장·전달
제작 시작작업 draft·빈 로그·분석 draft를 함께 생성한다.
분석 중분석 draft에 조사 결과·출처·분석·작성 중인 방향·한 일·남은 일을 저장한다.
분석 완료필수 출력을 검사하고 확정 분석·방향·참고 자료를 로그에 기록한다. 분석 단계를 완료하고 제작 draft를 생성한다.
제작 중제작 draft에 추가 조사·작성 중인 내용·한 일·남은 일을 저장한다. 실제 슬라이드는 기존 프로젝트에 저장한다.
제작 종료모든 장을 확인하고 최종 저장한다. 로그에 실제 제작 내용·활용 자료·추가 조사에 따른 변경 이유를 남기고 제작 실행을 종료한다.
중단·재개현재 단계의 draft와 이전 단계의 확정 출력을 읽고 이어간다. 완료한 단계는 다시 실행하지 않는다.
URL 등록실제 게시 시각·전체 이미지를 저장하고, 프로젝트 연결을 draft에서 로그로 옮긴다. 단계별 조사 기록을 로그에 보존하고 모든 draft를 삭제한다. 이 전체 저장은 한 번에 성공하거나 취소된다.

단계는 분석·방향 → 초안 제작 → 훅 검토·수정 → 시각 검증·수정 네 개다. 공통 성과 갱신, 외부 데스크탑 수정, 검토 대기·URL 등록은 단계별 draft에 넣지 않는다. 외부 수정은 기존 프로젝트에 반영되지만, 피드백 원문·수정 이유를 자동 저장하거나 조회하는 기능은 제공하지 않는다.

분석과 제작 방향은 같은 단계의 결과이므로 같은 분석 draft에 둔다. 제작 방향이 독립적으로 여러 개 생성·관리되는 구조가 아니므로 별도 direction 테이블은 두지 않는다. 제작 단계에는 이전 조사 전체를 복사하지 않고 확정 출력과 필요한 출처를 연결해서 읽는다.

값의 저장 방식

대상방식이유
분석TEXT관찰·해석·판단을 연결된 글로 읽는다.
제작 방향개별 컬럼소재·포맷 비교와 필수 출력 검사에 사용한다.
조사 결과·참고 자료JSON 배열출처·발견한 내용·참고할 부분·활용 이유가 여러 건 반복된다.
작성 중인 본문·슬라이드 구성JSON여러 장의 내용과 구조를 함께 읽고 저장한다.
실행 상태·시각·성과개별 컬럼상태 전환·조회·정렬·비교에 사용한다.

JSON에도 입력 구조와 유효성을 검사한다. 검색 응답이나 도구 호출 전체를 그대로 보관하는 용도가 아니다.

content_drafts

콘텐츠 제작 작업 전체의 상태만 관리한다. 조사 결과나 단계별 초안을 이 테이블에 넣지 않는다.

작성 중에는 빈 값을 허용한다. 완료할 때 분석과 제작 방향의 각 항목을 검사한다. 존재하지 않는 근거를 억지로 채우지 않는다. 제작 단계는 확정한 분석과 방향을 로그에서 읽고, 추가 맥락이 필요할 때 분석 draft의 조사 기록을 조회한다.

content_production_drafts

작업당 제작 단계 한 행이다. 분석 단계 완료 후 생성하며, 제작에 새로 필요한 컨텍스트만 저장한다.

실제 슬라이드 문서·사용 이미지는 기존 프로젝트 저장소에 저장한다. 이 테이블에 문서·이미지 전체를 복사하지 않는다. 게시 전에는 content_drafts.project_id, 게시 후에는 로그의 project_id로 연결한다. 문서·이미지는 복사하지 않는다.

아이디어나 제작 방향만 저장한 경우 draft_saved_at은 비워둔다. 실제 콘텐츠 초안부터 기록하며, 소재·포맷을 바꿔 다른 콘텐츠를 만들면 새 초안의 저장 시각으로 갱신한다. 중복 조정 시 작업 시작 시각 대신 이 시각과 실제 내용을 비교한다. 방향이 바뀐 초안은 로그의 원래 방향뿐 아니라 제작 draft의 현재 내용도 조회해 비교한다.

모든 단계에서 에이전트가 저장 API를 호출하고 프로그램이 DB 반영을 보장한다. 중단하면 마지막으로 저장한 지점부터 복구한다. 저장하지 않은 생각이나 CLI 프로세스 메모리는 복원하지 않는다. 완료율을 임의의 퍼센트로 추정하지 않고 단계 상태와 한 일·남은 일을 보여준다.

훅 검토는 본문과 CTA를 바꾸지 않는다. 시각 검증은 문구·이미지 정체성을 유지하고 배치·스타일만 수정한다. 각 실행에서 실제 참고 이미지와 최신 저장본 전체 장을 확인해야 통과한다. 통과하지 못하면 해당 단계에서 멈추고 마지막 저장 맥락으로 재개한다. 영어 폴리싱은 같은 검토 구조를 사용하며 텍스트 내용만 다듬는다. 웹 검색·외부 자료 조회·배치 수정은 허용하지 않는다. 게시 시 세 검토 테이블도 draft_context에 보존한 뒤 제거한다.

분석 완료 시 제작 전 판단을 기록한다. 제작 종료 시 실제 결과와 확정된 방향 안에서 추가 확인한 내용·수정 이유를 추가한다. 핵심 전제가 틀렸다면 근거와 막힌 부분을 남기고 중단하며 새 소재로 임의 전환하지 않는다. 중복 충돌은 분석 draft와 로그의 방향을 현재 선택으로 갱신하며 과거 선택을 별도 기록하지 않는다. 성과를 보고 기대나 판단을 사후 변경하지 않는다. 조사 후보 전부를 옮기지 않고 실제 사용한 자료와 활용 맥락을 남긴다. 내부 비교 집합은 지정 ID를 모두 조회해야 한다. 외부 참고 자료는 한도를 채울 의무가 없다.

성과는 개별 컬럼의 최신 값을 덮어쓴다. 제공되지 않는 값은 NULL로 두며 수집 실패 시 기존 값을 보존한다. 별도 성과 이력·수치 출처 컬럼은 두지 않는다.

피드백 저장·동기화 기능은 제외한다. 외부에서 직접 프로젝트를 수정할 수 있지만, 수정 이유를 자동으로 알거나 로그에 반영한다고 가정하지 않는다. 게시 당시 실제 모습은 URL 등록 시 별도로 보존한다.

제작 실행이 finished이고 로그의 completed_at이 없으면 검토·업로드 대기다. URL 등록은 별도 프로그램 처리이며, 필수 게시 정보와 전 장 이미지 저장이 끝나야 URL·게시 시각·이미지 연결·완료 시각을 함께 확정한다. 실패 시 등록 요청에 오류를 표시하고 재시도한다.

실제 게시 시각을 URL 등록 시각이나 기존 content_projects.published_at으로 대신 쓰지 않는다. 편집기 revision을 영구 콘텐츠 버전으로 간주하지 않는다. 플랫폼 게시물 ID는 필요할 때 URL에서 추출한다.

저장·조회 규칙

  • 작업 전체 draft와 로그는 1:1이다. 분석·초안·훅·시각 draft는 각 단계 시작 시 작업별 한 행을 만들며, 단계별 진행 내용은 해당 테이블에만 저장한다. 로그는 확정한 판단과 결과다.
  • 시각은 UTC ISO로 저장하고, 최근 게시물 갱신 날짜는 한국 시간으로 판단한다.
  • 프로젝트 삭제 시 로그·레퍼런스 연결은 NULL로 바꾼다. 내용이 있는 로그와 게시 당시 이미지 보존본은 남긴다. 프로젝트와 draft가 없고 분석·방향·내용·게시 정보가 모두 빈 로그는 제거한다.
  • 로그의 생성·실제 게시 시각과 draft의 실행 상태를 조회할 인덱스를 둔다. 표준 URL로 중복 연결을 막는다.
  • 성과 갱신은 성과 컬럼과 관측 시각만 변경한다. 기존 분석·기대·제작 방향을 바꾸지 않는다.
  • 저장·조회·상태 전환은 앱 API로 제공한다. 에이전트가 SQLite에 직접 쓰지 않는다.
