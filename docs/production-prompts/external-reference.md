# External origin contract (URL, saved reference, or automatic origin=spy)

Start from a blank project with production_create_project, using the preserved source's exact slide count.
Do not select or clone an internal project. On resume, keep and repair the already linked project,
including a draft created under an older workflow.

## Preserve composition; use the requested subject

For automatic origin=spy, use a NEW subject and substantive content, as established in analysis.
The source supplies composition only: exact page count/order, body progression, page roles and information roles.
Replace its concrete items, exercises, prescriptions, explanations and subject-specific artwork with content
appropriate to the new topic. Rewording the same list or correcting its claims is not a topic change.
For explicit external_url/spy_reference requests, keep the selected subject and verified substance unless
the user requests a topic change. This explicit-source rule does not apply to automatic requests.
Do not add setup, explanation, progression or summary pages. Map every original page to one replacement page.
Preserve body layout relationships: grouping, alignment, relative hierarchy, text/image placement,
and how information is represented. A star rating stays stars; a day-by-day table keeps its columns
and rest cells. Replacing either with a numeric badge or a loose row of figures loses information.
Adapt dimensions to 4:5 and readable English without redesigning that structure. Do not reproduce
platform UI, search bars, navigation arrows, watermarks or the reference account's branding.

Use our visual language: white (#FFFFFF) slide background, black (#000000) main text, red (#FF0000)
text emphasis, and gray secondary text. Use selective bold/color on meaningful words instead of
copying the external highlight bars, palette or decorative type treatment. Apply the supplied typography contract by text role; body text is at least 35px at 1080px slide width. Keep source body
hierarchy and alignment while changing these styles. Generate new illustrations with the attached
official character references; preserve their identity while matching the source's information role,
placement. For automatic variations, use the pose/action required by the NEW subject; do not copy the source exercise just to match its silhouette. External character images are composition evidence, not identity references.
Use real transparent artwork, editable text and shapes; do not paste source screenshots as slides.

## Our hook and CTA

Adapt the hook's wording to the requested subject and persona while preserving the source's framing and
hook-to-body relationship identified in analysis.presentation. Create its visual composition in our own
style; this visual freedom does not permit an unrelated opening promise. Do not preserve the external
cover layout. Apply the supplied hook typography, using black with selective red emphasis and at most one supporting phrase.
Make the official character illustration prominent and arrange a coherent, vertically centered group
with clear spacing. Use a CTA only in the source's existing closing slot; do not append a page. CTA uses our typography and the selected product's facts and CTA, subject to user
instructions. Never carry over the reference account's product, handle, logo or badge.

## Existing node responsibilities

Analysis reads the caption and every source slide to identify composition, then verifies the requested new content. For automatic requests, explicitly contrast the original subject with the new subject and identify what changes in each source slot. In answer, give the
usable content; in presentation, identify source page roles and body layouts to retain, including
information representations and the new subject-specific content in each corresponding slot. Specify what changes for our style,
hook and product CTA. Distinguish factual corrections from design adaptation. Do not add a separate
design-analysis step or hunt for an internal layout. Record the external source in sources with
clone_project_id=null.

Production receives all source slides with the official identity references. Implement presentation
from the blank document, save slide_plan before generating images, and compare the actual body to
the corresponding source pages. Hook refines the adapted opening within the source-to-body relationship; polish refines the persona's English
without losing the approved new content or reverting to the source subject. Visual receives all source slides too: compare body grouping,
sequence, alignment and representations against the source and presentation, and fix unjustified
composition deviations as well as readability, clipping and identity defects. A new subject, item, exercise, prescription or depiction required by the approved automatic topic is an intended content replacement, not a format defect. Do not restore the source content while checking composition. A documented factual correction or user request can also justify a difference. Do not restore an internal clone badge in this workflow.

Source images are captured once before analysis and stored locally. Production and visual receive those stored
images; hook and polish use the saved plan and can read stored images if needed. Never recollect the account
or post in a later stage. Automatic requests retain the automatic overlap check; explicit requests remain exempt.
