# 게시용 슬라이드 제작 가이드

Content Studio에서 게시용 슬라이드를 생성·수정할 때 적용한다. MCP로 프로젝트를 선택·복제·편집하는 작업도 포함하며, 앱 자체의 UI 개발에는 적용하지 않는다. 새 슬라이드 작업을 시작할 때 이 문서의 최신 내용을 읽는다.

이번 작업에 대한 사용자의 명시적 요청 → 이 가이드 순서로 적용한다. 사용자가 요청한 예외는 해당 작업에만 적용한다.

## 1. 제작할 내용을 정한 뒤 리서치한다

주제와 핵심 메시지는 사용자 요청이나 별도의 콘텐츠 기획에서 정한다. 요청이 모호할 때의 범위 확인은 [AGENTS.md](../AGENTS.md#콘텐츠-제작의-범위)를 따른다.

- 사용자가 레퍼런스·주제를 지정했다면 그 요청을 우선한다.
- 플랫폼을 지정하지 않았다면 TikTok·Instagram을 기본 조사 대상으로 삼는다. 선택한 주제의 실제 게시물 이미지·영상·본문을 직접 확인해 훅과 전개 방식을 파악한다. 검색 제목·요약만으로 선정하지 않는다.
- 레퍼런스를 그대로 반복하지 않고 이번 콘텐츠의 메시지에 맞게 새 문구를 작성한다. 반응 지표는 설명 방식의 참고이고 사실성의 근거가 아니다. 댓글 본문은 수집하지 않는다.
- 출처와 활용한 설명 방식·수집 시점, 확인한 반응 지표를 작업 메모 또는 최종 설명에 남긴다. 확인 가능한 레퍼런스가 없으면 조사 범위와 이유를 설명하고 멈춘다. 조건을 임의로 낮추거나 출처를 지어내지 않는다.

## 2. 선택한 주제의 사실과 효과를 검증한다

플랫폼 조사는 정한 주제의 소재와 전달 방식을 구체화하는 단계이고, 근거 조사는 주장할 수 있는 범위를 판단하는 단계다. 조사 결과에 따라 메시지를 좁히거나 바꾼다. 정해둔 결론에 맞는 근거만 고르지 않는다.

- 사실·효과·과학적·수치적 주장을 새로 만들거나 바꾸면, 연구와 신뢰할 수 있는 원문을 확인한다. 연구 대상, 비교 조건, 측정 결과가 게시할 주장과 맞는지 판단한다. 기존 근거는 주제 적합성과 최신성을 확인한 뒤 재사용할 수 있다.
- 검색 요약, 플랫폼 게시물, 댓글과 개인 경험만으로 효과를 확정하지 않는다. 사실, 연구 결과, 해석, 개인 경험을 구분하고 근거가 허용하는 수준으로 표현한다. 근거가 약하거나 충돌하면 주장을 좁히거나 제외한다.
- 핵심 주장과 근거 출처의 연결을 작업 메모 또는 최종 설명에 남긴다. 출처와 사용자 반응을 지어내지 않는다.
- 훅이 약속하는 이득이나 피할 손해는 본문에서 뒷받침한다. 효과를 과장하거나 불안을 만들어내지 않는다. 주제에 맞으면 궁금증·공감·안도감을 활용한다.
- 기존 콘텐츠의 색상·크기·배치만 수정한다면 새 플랫폼 조사나 관련 없는 근거 조사를 반복하지 않는다.

## 3. 내용에 맞게 구조와 배치를 만든다

자동 제작은 분석 단계에서 정한 내용으로 새 프로젝트를 생성한다. 과거 게시글과 선별 레퍼런스의 실제 이미지를 참고해 구조·배치를 정한다. 소재·답·문구·이미지·페이지 흐름은 이번 콘텐츠에 맞게 작성한다. 고정 템플릿이나 별도의 공통 시각 언어 문서는 사용하지 않는다.

- 자동 제작은 `create_project` 또는 작업 전용 `production_create_project`를 사용한다. `clone_project`는 사용자가 기존 게시글 복사를 요청한 경우 `projectId`로 독립 사본을 만든다. 원본을 덮어쓰지 않는다.
- 참고한 자료에서 어떤 부분을 왜 활용했는지 로그에 남긴다. 시각적으로 비슷하다는 이유만으로 이전 주제·주장을 답습하지 않는다.
- 페이지·카드 수와 정보 구조는 독자가 얻을 답에 맞게 조정한다. 글자 넘침·잘림·겹침을 해결하고 불필요한 설명은 줄인다.
- **공유 구조:** 여러 본문 페이지에서 함께 수정할 요소는 같은 Element를 재사용한다. 문구·이미지가 달라도 새 Element를 만들 이유가 되지 않는다. 페이지별 내용은 placement의 값에, 개별 폴리싱은 local 덮어쓰기에 둔다. 새 요소를 추가하기 전에 기존 정의를 확인한다.
- **편집 배치와 경고:** 관련 명령은 `edit_project`의 한 `commands` 배열로 모은다. 쓰기 결과의 `warnings`에서 공유 누락 후보를 확인하고, 함께 수정할 대상이면 `rebind_element`로 연결한 뒤 필요한 공통값·개별값을 정리한다. 독립적으로 관리할 대상이면 경고를 유지할 수 있으며 판단을 완료 보고에 남긴다. 검증은 시각적 유사성에 기반하므로 경고만으로 무조건 병합하지 않는다. 도구 계약과 검증 코드 위치는 [AGENTS.md](../AGENTS.md#mcp-연결과-프로젝트-작업)를 따른다.
- 모든 페이지의 배경은 `#FFFFFF`로 맞춘다. 이미지 내부 배경과 정보 구분용 강조 영역은 유지할 수 있다.
- 사용자가 지정한 자산과 참조 범위를 지킨다. 필요한 이미지가 없으면 슬롯을 비워 두고 누락을 알린다. 이전 주제의 이미지를 남기거나 무관한 이미지로 대체하지 않는다.
- 문구는 미국 TikTok 독자에게 자연스러운 영어로 작성한다. 사용자가 다른 언어·독자를 지정했다면 그 기준을 따른다. 직역투, 상투적인 AI 표현, 모호한 문장과 반복을 줄인다.

## 4. 전체 결과를 검토하고 저장을 확인한다

도구의 성공 응답만으로 완료를 판단하지 않는다.

- **시각:** 모든 페이지를 미리보기로 확인한다. 참고한 이미지의 시각적 방향, 글자 넘침·잘림·겹침·대비, 이미지 크기·비율을 점검한다. 이미지는 슬롯별로 조정하며 하나의 크기를 일괄 적용하지 않는다.
- **내용:** 필수 정보와 전개 순서, 훅과 본문의 일치, 주장과 근거의 연결, 이전 게시글 내용의 잔존 여부를 확인한다.
- **언어:** 모든 슬라이드와 제목·캡션·해시태그의 문법, 자연스러움, 반복, 용어와 메시지의 일관성을 확인한다.
- **메타데이터:** 최종 주제와 메시지를 프로젝트에 저장한다. 구성은 재사용 설명이며 게시글의 구체적인 내용을 담지 않는다. 제작 완료를 게시 완료로 등록하지 않는다.
- **완료 보고:** 편집한 결과가 저장됐는지 확인하고 프로젝트 링크를 제공한다. 플랫폼 레퍼런스와 근거 출처를 함께 남기며, 누락 자산이나 확인하지 못한 부분이 있으면 명시한다.
