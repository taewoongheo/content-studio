# 슬라이드 생성과 재사용 지침

이 문서는 Codex가 Content Studio에서 게시용 슬라이드를 생성·수정할 때 지키는 제약이다. 새 슬라이드 프로젝트는 반드시 등록된 템플릿 프로젝트를 복제하여 만든다. 기존 프로젝트의 시각적 구조와 공통 스타일을 물려받고, 이번 주제에 맞게 내용을 교체한다. Content Studio 앱 자체의 UI 디자인에는 적용하지 않는다.

## 템플릿 프로젝트의 의미

템플릿 프로젝트는 별도의 문서나 복사본이 아니다. 기존 프로젝트 원본이 템플릿으로 등록된 상태다. 대시보드의 템플릿 목록은 해당 원본을 참조한다.

- 템플릿을 등록할 때 프로젝트나 슬라이드를 복제하지 않는다.
- 템플릿 원본을 수정하면 이후 복제에 사용하는 내용도 바뀐다.
- 템플릿 등록을 해제해도 원본 프로젝트는 삭제하지 않는다.
- 원본을 삭제하면 템플릿 목록에서도 제거된다.
- 새 게시글 제작을 위한 복제본은 독립적인 프로젝트이며 템플릿으로 자동 등록하지 않는다.
- 템플릿 원본 수정이 이미 만든 게시글에 소급 반영되지는 않는다.

## 생성과 선택의 제약

- 새 프로젝트는 `clone_project`로 등록된 템플릿 프로젝트에서만 생성한다. 빈 프로젝트 생성, 미등록 프로젝트 복제, DB 직접 쓰기나 다른 경로를 통한 우회 생성은 허용하지 않는다.
- 등록된 템플릿이 없으면 생성할 수 없다. 대시보드에서 기존 프로젝트에 재사용 가이드를 작성하고 템플릿으로 등록해야 한다는 점을 알린다.
- 템플릿 선택은 `list_template_guides`가 반환하는 재사용 가이드와 목록 메타데이터로만 판단한다. 후보를 비교하기 위해 전체 프로젝트 JSON, 이미지 자산, 슬라이드 미리보기를 읽지 않는다.
- 완벽히 일치하는 포맷이 없어도 등록된 템플릿 중 가장 가까운 하나를 선택한다. 포맷 불일치를 이유로 처음부터 새로 만들지 않는다.
- 주제나 이름이 비슷하다는 이유만으로 선택하지 않는다. 재사용 가이드에 적힌 역할, 필수 정보, 시각적 구성과 정보량이 이번 요청에 얼마나 적합한지 판단한다.
- 사용자가 특정 템플릿을 지정하면 그 선택을 따른다. 미등록 프로젝트를 지정했더라도 임의로 등록하거나 미등록 원본 복제로 우회하지 않는다.
- 선택이 끝난 뒤의 편집에는 해당 프로젝트 JSON과 미리보기를 사용할 수 있다. 이를 다른 후보를 비교하기 위한 선택 자료로 사용하지 않는다.
- AI가 게시글을 만들었다는 이유로 템플릿을 자동 등록하거나, 새 게시글에 맞추기 위해 템플릿 원본을 수정하지 않는다.

## 재사용 가이드

재사용 가이드는 각 프로젝트가 어떤 슬라이드 유형과 상황에 적합한지 설명하는 DB 저장 정보다. 제목이나 현재 주제를 요약하는 데 그치지 않고 다른 주제로도 재사용할 수 있는 조건을 설명한다. 대시보드에서 편집할 수 있으며, Codex는 `set_reuse_guide`로 저장할 수 있다. 템플릿 등록과 해제는 대시보드에서 관리한다.

가이드에는 다음 정보를 간결하게 담는다.

- **콘텐츠 역할:** 운동 루틴 소개, 선택지 비교, 대체 방법 제시, 오해 교정 등 독자가 얻는 가치.
- **필수 정보:** 이미지, 운동명, 세트·횟수, 비교 기준 등 구조가 수용하는 정보.
- **시각적 구성:** 훅과 본문 구성, 카드 배치, 계정 뱃지 등 재사용할 구조.
- **적합한 상황과 제약:** 어떤 요청에 적합하고, 어느 정도의 정보량이나 이미지 수를 수용하는지.

예시:

> 운동별 이미지와 세트·횟수를 보여주는 루틴 소개에 적합하다. 등·가슴·어깨 등 다른 부위의 루틴에 재사용할 수 있다. 큰 제목의 훅 페이지, 페이지당 운동 카드 2개가 반복되는 본문, 계정 뱃지를 포함한다. 긴 비교 설명보다는 짧은 운동 설명에 적합하다.

가이드를 새로 작성할 때는 프로젝트의 페이지 구성과 요소의 역할을 참고한다. 실제 문서와 맞지 않는 구성이나 기능을 지어내지 않는다. 이 확인은 가이드 작성·정비를 위한 것이며, 새 게시글의 템플릿 선택 단계에서 전체 JSON을 읽을 이유가 되지 않는다.

주제와 문구만 바뀌었다고 가이드를 매번 새로 작성하지 않는다. 페이지 역할, 카드 구성, 필요한 정보, 레이아웃이 바뀌어 기존 가이드가 부정확해졌다면 갱신한다. 실제로 저장하지 않은 가이드를 저장 완료라고 보고하지 않는다.

## 복제 후 유지와 변경의 범위

- **기본적으로 유지:** 훅·본문의 폰트와 스타일, 카드 모양, 정렬과 간격, 계정 뱃지 등 원본의 시각적 규칙. 별도 요청 없이 새로 디자인하지 않는다.
- **이번 주제에 맞춰 교체:** 훅 문구, 본문, 이미지, 운동 정보, 제목, 캡션과 해시태그. 이전 게시글의 내용이 남지 않도록 확인한다.
- **필요할 때 조정:** 페이지와 카드 수, 요소 추가·삭제, 정보량 변화로 생긴 넘침과 잘림을 해결하는 크기와 배치. 기존 스타일을 활용하고 변경 범위를 최소화한다.
- 요소를 추가할 때는 기존의 비슷한 역할을 가진 요소의 스타일을 활용한다. 다른 포맷에 필요한 요소를 추가한다는 이유로 전체 스타일을 바꾸지 않는다.
- 사용자가 제공한 자산과 참조 범위를 지킨다. 필요한 이미지가 없으면 이전 주제의 이미지를 새 콘텐츠의 이미지처럼 남기거나 다른 이미지로 조용히 대체하지 않는다. 누락을 표시한다.

## 공통 규칙과 우선순위

이번 작업에 대한 사용자의 명시적 요청을 가장 먼저 따른다. 그다음 아래 공통 고정 규칙을 적용하고, 나머지 시각적 규칙은 선택한 템플릿에서 유지한다. 템플릿의 설정이 공통 규칙과 충돌하면 충돌하는 부분만 수정한다. 사용자가 고정 규칙의 예외를 명시했다면 그 예외는 이번 작업에만 적용한다.

- **고정 규칙:** 모든 슬라이드 페이지의 배경은 흰색 `#FFFFFF`이다. 이미지 내부 배경이나 정보 구분용 강조 영역까지 흰색으로 바꿀 필요는 없다.
- **고정 규칙:** 사실, 연구 결과, 해석, 커뮤니티의 경험을 구분한다. 근거가 허용하는 수준보다 강하게 단정하지 않는다.
- **고정 규칙:** 훅의 약속은 본문에서 뒷받침한다. 효과를 과장하거나 관심을 끌기 위해 불안을 만들어내지 않는다.
- **고정 규칙:** 슬라이드 문구와 제목·캡션·해시태그는 사용자가 요청한 언어로 작성한다.
- **기본값:** 훅은 독자가 얻을 이득이나 피할 손해를 구체적으로 드러내어 감정을 건드린다. 맞지 않는 경우 궁금증·공감·안도감 등으로 계속 읽을 이유를 제시할 수 있다.

## 조사와 근거의 제약

- 과학적·수치적 주장을 새로 만들거나 바꾸면 필요한 근거를 조사한다. 검증된 기존 근거는 주제 적합성과 최신성을 확인한 뒤 재사용할 수 있다.
- 연구와 신뢰할 수 있는 원문을 우선 확인하고 대상, 비교 조건, 측정 결과가 게시할 주장과 맞는지 판단한다. 검색 요약만으로 강한 주장을 확정하지 않는다.
- 커뮤니티는 반복되는 고민, 사용 상황, 반론, 실제 공감 언어를 찾는 데 활용한다. 댓글과 개인 경험을 효과의 과학적 증거로 취급하지 않는다.
- 한 사람의 표현을 전체 사용자의 의견으로 일반화하지 않는다. 출처나 사용자 반응을 지어내지 않는다.
- 근거가 약하거나 충돌하면 주장을 좁히거나 제외한다. 핵심 주장과 출처의 연결은 작업 메모 또는 최종 설명에 남긴다.
- 색상·크기·배치만 수정할 때 관련 없는 새 조사를 반복하지 않는다.

## 결과 검토의 제약

지침을 읽었다는 사실이나 도구의 성공 응답만으로 완료를 판단하지 않는다.

- 모든 페이지의 배경과 시각적 속성을 확인한다. 원본에서 물려받아야 할 훅·본문·계정 뱃지 스타일이 불필요하게 바뀌지 않았는지 확인한다.
- 모든 페이지를 미리보기로 확인한다. 글자 넘침, 잘림, 겹침, 대비, 이미지 크기와 비율을 확인한다. 이미지는 각 슬롯의 영역에 맞춰 조정하며 하나의 크기를 일괄 적용하지 않는다.
- 원본 게시글의 문구와 이미지가 새 주제에 맞지 않게 남아 있지 않은지 확인한다. 계정 뱃지 같은 공통 정보는 유지한다.
- 필수 정보, 흐름, 훅과 본문의 일치, 주장과 근거의 연결을 확인한다.
- 문법, 모호한 표현, 반복 의미, 용어 일관성, 제목·캡션·해시태그의 정합성을 확인한다.
- 확인 도구가 없거나 검토를 완료할 수 없으면 확인한 범위와 남은 항목을 명시한다. 보지 않은 화면을 검증 완료라고 보고하지 않는다.

한 번의 수정 요청을 모든 슬라이드의 새 고정 규칙으로 확대하지 않는다. 사용자가 앞으로도 적용하라고 명시한 경우에 해당 범위의 지침을 갱신한다.
