# 게시용 슬라이드 제작 가이드

Content Studio에서 게시용 슬라이드를 생성·수정할 때 적용한다. MCP로 프로젝트를 선택·복제·편집하는 작업도 포함하며, 앱 자체의 UI 개발에는 적용하지 않는다. 새 슬라이드 작업을 시작할 때 이 문서의 최신 내용을 읽는다.

이번 작업에 대한 사용자의 명시적 요청 → 이 가이드 순서로 적용한다. 사용자가 요청한 예외는 해당 작업에만 적용한다.

## 1. 과거 기록과 외부 자료에서 개선할 내용을 정한다

주제와 핵심 메시지는 사용자 요청이나 콘텐츠별 분석에서 정한다. 요청이 모호할 때의 범위 확인은 [AGENTS.md](../AGENTS.md#콘텐츠-제작의-범위)를 따른다.

- 소재는 과거 게시글의 성과·실제 내용과 인터넷·커뮤니티 조사를 함께 보고 고른다. 훅·표현 방식은 과거 게시글과 외부 레퍼런스의 실제 내용·이미지를 참고한다. 반응 지표와 이전 판단을 살펴 이번 독자에게 제공할 답을 개선한다.
- 자동 제작의 분석 단계에서는 상위 사례뿐 아니라 하위 사례의 반응이 낮았던 이유도 비교·추정하고 이번 제작에 반영한다. 구체적인 분석·기록 방식은 [분석 단계 지침](production-prompts/analysis.md)을 따른다.
- 이전 소재·문구를 그대로 반복하지 않는다. 최근 콘텐츠와 비교해 새롭게 제공할 답과 선택 이유를 남긴다.
- 지정 계정에서 수집해 자료함에 저장한 외부 후보는 실제 내용·이미지와 타겟 적합성을 확인한 뒤 참고한다. 수집 범위와 선별 기준은 [리서치 기준](research-guidelines.md)을 따른다. 에이전트가 별도 TikTok·Instagram 피드를 탐색하지 않는다.
- 분석 단계에서는 인터넷·커뮤니티에서 소재 후보와 독자의 상황을 조사한다. 제작 중에는 현재 내용에 필요한 질문이 생기면 추가로 확인한다. 출처와 해석 기준은 [리서치 기준](research-guidelines.md)을 따른다.

## 2. 독자에게 줄 답과 표현을 확인한다

- 주제가 독자의 어떤 상황·욕구와 연결되는지, 어떤 답을 완성해 줄지 분명히 한다. 기존 소재를 보기 좋게 바꾸는 것만으로 선택 이유를 대신하지 않는다.
- 실제 확인한 사실·경험과 에이전트의 해석을 구분한다. 출처에 없는 효과·수치·사용자 반응을 만들지 않는다. 확인하지 못한 주장은 범위를 좁히거나 제외한다.
- 사용한 출처와 이번 판단의 연결을 작업 기록에 남긴다.
- 훅이 약속하는 이득이나 피할 손해는 본문에서 충족한다. 효과를 과장하거나 불안을 만들어내지 않는다. 주제에 맞으면 궁금증·공감·안도감을 활용한다.
- 색상·크기·배치만 수정한다면 관련 없는 조사를 반복하지 않는다.

## 3. 내용에 맞게 구조와 배치를 만든다

자동 제작은 분석 단계에서 정한 내용으로 새 프로젝트를 생성한다. 과거 게시글과 외부 레퍼런스의 실제 이미지를 참고해 구조·배치를 정한다. 소재·답·문구·이미지·페이지 흐름은 이번 콘텐츠에 맞게 작성한다. 고정 템플릿이나 별도의 공통 시각 언어 문서는 사용하지 않는다.

- 자동 제작은 `create_project` 또는 작업 전용 `production_create_project`를 사용한다. `clone_project`는 사용자가 기존 게시글 복사를 요청한 경우 `projectId`로 독립 사본을 만든다. 원본을 덮어쓰지 않는다.
- 참고한 자료에서 어떤 부분을 왜 활용했는지 로그에 남긴다. 시각적으로 비슷하다는 이유만으로 이전 주제·주장을 답습하지 않는다.
- 페이지 수와 정보 구조는 독자가 얻을 답에 맞게 조정한다. 아래 시각 규칙을 지키도록 정보를 나누며, 글자를 줄여 억지로 한 장에 넣지 않는다.
- **공유 구조:** 여러 본문 페이지에서 함께 수정할 요소는 같은 Element를 재사용한다. 문구·이미지가 달라도 새 Element를 만들 이유가 되지 않는다. 페이지별 내용은 placement의 값에, 개별 폴리싱은 local 덮어쓰기에 둔다. 새 요소를 추가하기 전에 기존 정의를 확인한다.
- **편집 배치와 경고:** 관련 명령은 `edit_project`의 한 `commands` 배열로 모은다. 쓰기 결과의 `warnings`에서 공유 누락 후보를 확인하고, 함께 수정할 대상이면 `rebind_element`로 연결한 뒤 필요한 공통값·개별값을 정리한다. 독립적으로 관리할 대상이면 경고를 유지할 수 있으며 판단을 완료 보고에 남긴다. 검증은 시각적 유사성에 기반하므로 경고만으로 무조건 병합하지 않는다. 도구 계약과 검증 코드 위치는 [AGENTS.md](../AGENTS.md#mcp-연결과-프로젝트-작업)를 따른다.
- 모든 페이지의 배경은 `#FFFFFF`로 맞춘다. 이미지 내부 배경과 정보 구분용 강조 영역은 유지할 수 있다.
- 사용자가 지정한 자산과 참조 범위를 지킨다. 필요한 이미지가 없으면 누락을 기록하고 미완료로 남긴다. 이미지가 없는 페이지를 완성으로 승인하거나, 이전 주제·무관한 이미지로 수량을 채우지 않는다.
- 문구는 미국 TikTok 독자에게 자연스러운 영어로 작성한다. 사용자가 다른 언어·독자를 지정했다면 그 기준을 따른다. 직역투, 상투적인 AI 표현, 모호한 문장과 반복을 줄인다.

### 시각 규칙

과거 게시글과 레퍼런스보다 아래 규칙을 우선한다. 훅·본문·CTA 모든 페이지에 적용한다.

- **이미지:** 페이지마다 내용을 전달하는 이미지를 1~3개 배치한다. 가능하면 1~2개에 집중하고 3개를 넘기지 않는다. 배경·장식·LIFTCODE 뱃지는 이 수에 포함하지 않는다.
- **이미지 우선:** 이미지가 먼저 눈에 들어오도록 크게 배치한다. 이미지 프레임이나 원본 일부가 슬라이드 밖으로 나가도 된다. 실제로 내보낸 슬라이드 안에서 핵심 자세·동작·비교 대상이 명확하면 허용한다. 프레임 전체를 안에 넣으려고 이미지를 작게 줄이지 않는다. 운동을 이해하는 데 필요한 부위·기구 연결·동작 차이는 잘리지 않아야 한다.
- **텍스트 크기:** 1080px 너비의 슬라이드 기준으로 일반 텍스트는 최소 35px로 한다. 이는 하한이며 모든 문구를 같은 크기로 맞추라는 뜻이 아니다. 아래 고정 LIFTCODE 뱃지만 25px 예외를 적용한다. 글자가 많으면 정보를 나누거나 문구를 정리하며, 최소 크기 아래로 줄이지 않는다.
- **서체:** Oswald는 훅·CTA 페이지에서만 사용할 수 있다. 본문 페이지는 제목·소제목·본문·수치·뱃지를 포함해 Inter만 사용한다. 훅·CTA에서도 모든 문구를 Oswald로 쓸 필요는 없으며 보조 설명은 Inter를 사용할 수 있다.
- **핵심 문구:** 독자가 답을 이해하고 실행하는 데 필요한 문구만 남긴다. 제목의 반복, 당연한 설명, 장식용 영문 라벨, 작은 주석과 부가 문구를 주변에 흩뿌리지 않는다. 설명을 무조건 삭제하는 것이 아니라 불필요한 보조 텍스트를 제거한다. 운동명·세트·횟수·판단 조건처럼 답에 필요한 정보는 유지한다.
- **타이포 위계:** 페이지에서 먼저 읽을 핵심 답을 하나 정하고 제목·핵심 수치·설명의 중요도에 맞춰 크기 차이가 한눈에 보이게 한다. 작은 크기 차이나 색상만으로 위계를 대신하지 않는다. 같은 역할에는 같은 크기·굵기를 쓰고, 보조 라벨·설명을 제목처럼 크고 굵게 만들어 핵심과 경쟁시키지 않는다.
- **간격과 그룹:** 제목과 그에 속한 답·수치·설명을 하나의 정보 묶음으로 배치한다. 묶음 내부 간격은 서로 다른 묶음 사이 간격보다 작게 두고, 같은 관계의 간격과 정렬선을 페이지마다 유지한다. 텍스트 상자의 빈 프레임이 아니라 실제 보이는 글자 사이의 간격으로 판단한다.
- **읽는 흐름:** 텍스트를 화면 곳곳에 독립적으로 흩어 놓지 않는다. 제목 → 핵심 답·수치 → 필요한 설명으로 읽는 경로가 이어지게 하고, 설명은 관련 대상 가까이에 둔다. 여백은 묶음을 구분하고 핵심을 강조하는 데 사용하며, 빈 공간을 채우려고 중복 제목·추상적 라벨·장식 문구를 추가하지 않는다. 본문은 의미 단위로 줄을 바꾸고, 불필요하게 좁은 상자로 짧은 줄을 여러 개 만들지 않는다.
- **LIFTCODE 뱃지:** 모든 페이지의 하단 왼쪽에 배치한다. 배경은 검은색(#000000), 문구는 LIFTCODE, 서체는 Inter, 글자 크기는 25px, 굵기는 700, 글자색은 흰색(#FFFFFF)으로 고정한다. 너비는 슬라이드 너비의 17.9%, 높이는 슬라이드 높이의 4.6%, 모서리 반경은 99px다. 페이지마다 같은 하단·왼쪽 여백을 유지한다. 뱃지 글자는 일반 텍스트 최소 35px 규칙의 예외이며, 과거 게시글의 큰 뱃지를 따라 확대하지 않는다. 이미지 뒤에 가려지거나 슬라이드 밖으로 잘리지 않아야 한다.

## 4. 전체 결과를 검토하고 저장을 확인한다

도구의 성공 응답만으로 완료를 판단하지 않는다.

- **시각:** 모든 페이지를 실제 미리보기 이미지로 확인한다. 페이지별 이미지 수·이미지 우선 배치·최소 글자 크기·서체·텍스트 위계·하단 왼쪽 뱃지와 참고 이미지의 시각적 방향을 점검한다. 최종 슬라이드 경계 안의 화면으로 판단하며 의도적인 이미지 넘침은 오류로 취급하지 않는다. 텍스트 잘림·겹침, 핵심 자세의 손실, 낮은 대비는 수정한다.
- **내용:** 필수 정보와 전개 순서, 훅과 본문의 일치, 주장과 실제 확인 내용의 일치, 이전 게시글 내용의 잔존 여부를 확인한다.
- **언어:** 모든 슬라이드와 제목·캡션·해시태그의 문법, 자연스러움, 반복, 용어와 메시지의 일관성을 확인한다.
- **메타데이터:** 최종 주제와 메시지를 프로젝트에 저장한다. 구성은 재사용 설명이며 게시글의 구체적인 내용을 담지 않는다. 제작 완료를 게시 완료로 등록하지 않는다.
- **완료 보고:** 편집한 결과가 저장됐는지 확인하고 프로젝트 링크를 제공한다. 참고한 과거 게시글·지정 레퍼런스와 조사 출처를 남기며, 누락 자산이나 확인하지 못한 부분이 있으면 명시한다.
