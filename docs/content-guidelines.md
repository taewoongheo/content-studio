# 게시용 슬라이드 제작 가이드

Content Studio에서 게시용 슬라이드를 생성·수정할 때 적용한다. MCP로 프로젝트를 선택·복제·편집하는 작업도 포함하며, 앱 자체의 UI 개발에는 적용하지 않는다. 새 슬라이드 작업을 시작할 때 이 문서의 최신 내용을 읽는다.

이번 작업에 대한 사용자의 명시적 요청 → 이 가이드 순서로 적용한다. 사용자가 요청한 예외는 해당 작업에만 적용한다.

## 1. 과거 기록과 외부 자료에서 개선할 내용을 정한다

소재와 핵심 메시지는 사용자 요청이나 콘텐츠별 분석에서 정한다. 요청이 모호할 때의 범위 확인은 [AGENTS.md](../AGENTS.md#콘텐츠-제작의-범위)를 따른다.

- 소재는 분석 자료 노드가 전달한 내부 게시글의 성과·실제 내용과 외부 콘텐츠 레퍼런스를 보고 고른다. 훅·표현 방식은 과거 게시글과 외부 레퍼런스의 실제 내용·이미지를 참고한다. 반응 지표와 이전 판단을 살펴 이번 독자에게 제공할 답을 개선한다.
- 자동 제작의 분석 단계에서는 상위 사례뿐 아니라 하위 사례의 반응이 낮았던 이유도 비교·추정하고 이번 제작에 반영한다. 구체적인 분석·기록 방식은 [분석 단계 지침](production-prompts/analysis.md)을 따른다.
- 이전 소재·문구를 그대로 반복하지 않는다. 최근 콘텐츠와 비교해 새롭게 제공할 답과 선택 이유를 남긴다.
- 지정 계정에서 수집해 자료함에 저장한 외부 후보는 실제 내용·이미지와 타겟 적합성을 확인한 뒤 참고한다. 수집 범위와 선별 기준은 [리서치 기준](research-guidelines.md)을 따른다. 에이전트가 별도 TikTok·Instagram 피드를 탐색하지 않는다.
- 분석에서는 내부 게시글·외부 레퍼런스를 비교해 소재를 정한다. 소재 선정 이후 초안·훅에서 필요한 사실과 커뮤니티의 실제 표현·상황을 확인한다. 출처와 해석 기준은 [리서치 기준](research-guidelines.md)을 따른다.

## 2. 독자에게 줄 답과 표현을 확인한다

- 소재가 독자의 어떤 상황·욕구와 연결되는지, 어떤 답을 완성해 줄지 분명히 한다. 기존 소재를 보기 좋게 바꾸는 것만으로 선택 이유를 대신하지 않는다.
- 실제 확인한 사실·경험과 에이전트의 해석을 구분한다. 출처에 없는 효과·수치·사용자 반응을 만들지 않는다. 확인하지 못한 주장은 범위를 좁히거나 제외한다.
- 사용한 출처와 이번 판단의 연결을 작업 기록에 남긴다.
- 훅이 약속하는 이득이나 피할 손해는 본문에서 충족한다. 효과를 과장하거나 불안을 만들어내지 않는다. 소재에 맞으면 궁금증·공감·안도감을 활용한다.
- 색상·크기·배치만 수정한다면 관련 없는 조사를 반복하지 않는다.

## 3. 내용에 맞게 구조와 배치를 만든다

자동 제작 초안은 분석 단계에 전달된 최대 30개 내부 게시글 안에서 포맷·정보 구성·이미지 수·시각적 완성도가 적합한 하나를 골라 배치를 복제한다. 과거 게시글과 외부 레퍼런스의 실제 이미지는 초안에서 참고한다. 소재·답·문구·이미지·페이지 흐름은 이번 콘텐츠에 맞게 작성한다. 고정 템플릿이나 별도의 공통 시각 언어 문서는 사용하지 않는다. 복제한 배치는 출발점이며 내용에 맞게 장 수·크기·위치·구조를 바꿀 수 있다. 시각 검증에는 원본 레퍼런스를 전달하지 않으며 현재 결과와 이 가이드만으로 조정한다.

- 자동 제작의 화면 비율은 **4:5 (1080 × 1350)**로 고정한다. 원본의 비율이 달라도 새 초안은 4:5로 만들고 해당 비율에 맞춰 배치를 조정한다.
- 자동 제작은 `production_clone_project`로 저장본의 구조·공유 요소·서체·배치·간격을 독립 사본에 복제한다. 원본 문구와 이미지 값은 비우고 뱃지는 유지하며 원본 자산 바이트는 복사하지 않는다. 초안에서 새 문구와 이미지를 채운다. 원본은 수정하지 않는다. `clone_project`는 일반 수동 복제 경로다.
- 참고한 자료에서 어떤 부분을 왜 활용했는지 로그에 남긴다. 시각적으로 비슷하다는 이유만으로 이전 소재·주장을 답습하지 않는다. 분석과 초안에서 참고 이유를 기록하고 시각 검증에서는 출처 비교를 하지 않는다.
- 페이지 수와 정보 구조는 독자가 얻을 답에 맞게 조정한다. 아래 시각 규칙을 지키도록 정보를 나누며, 글자를 줄여 억지로 한 장에 넣지 않는다.
- **공유 구조:** 여러 본문 페이지에서 함께 수정할 요소는 같은 Element를 재사용한다. 문구·이미지가 달라도 새 Element를 만들 이유가 되지 않는다. 페이지별 내용은 placement의 값에, 개별 폴리싱은 local 덮어쓰기에 둔다. 새 요소를 추가하기 전에 기존 정의를 확인한다.
- **편집 배치와 경고:** 관련 명령은 `edit_project`의 한 `commands` 배열로 모은다. 쓰기 결과의 `warnings`에서 공유 누락 후보를 확인하고, 함께 수정할 대상이면 `rebind_element`로 연결한 뒤 필요한 공통값·개별값을 정리한다. 독립적으로 관리할 대상이면 경고를 유지할 수 있으며 판단을 완료 보고에 남긴다. 검증은 시각적 유사성에 기반하므로 경고만으로 무조건 병합하지 않는다. 도구 계약과 검증 코드 위치는 [AGENTS.md](../AGENTS.md#mcp-연결과-프로젝트-작업)를 따른다.
- 모든 페이지의 배경은 `#FFFFFF`로 맞춘다. 정보 구분용 강조 영역은 유지할 수 있다.
- 사용자가 지정한 자산과 참조 범위를 지킨다. 필요한 이미지가 없으면 누락을 기록하고 미완료로 남긴다. 이미지가 없는 페이지를 완성으로 승인하거나, 이전 소재·무관한 이미지로 수량을 채우지 않는다.
- 문구는 미국 TikTok 독자에게 자연스러운 영어로 작성한다. 사용자가 다른 언어·독자를 지정했다면 그 기준을 따른다. 직역투, 상투적인 AI 표현, 모호한 문장과 반복을 줄인다.

### 시각 규칙

과거 게시글과 레퍼런스보다 아래 규칙을 우선한다. 훅·본문·CTA 모든 페이지에 적용한다.

- **이미지:** 페이지마다 내용을 전달하는 이미지를 1~2개 배치한다. 배경·장식·LIFTCODE 뱃지는 이 수에 포함하지 않는다.
- **투명 배경:** 새로 생성하는 이미지 자산은 항상 실제 투명 배경이어야 한다. 흰 배경이나 체크무늬를 그린 배경은 투명이 아니다. 슬라이드 배경은 별도로 흰색을 유지한다.
- **새 이미지:** 초안 제작에서 각 슬라이드의 내용에 맞는 장면·동작·기구·시점과 이미지 역할을 정하고 새로 생성한다. 과거 게시글·외부 자료의 이미지는 참고만 하며 자산을 가져와 배치하지 않는다. 한 콘텐츠 안에서도 같은 이미지를 여러 배치에 사용하지 않는다. 파일명·자산 ID만 바꾸는 것도 중복이다. 새로 생성한 이미지라면 자세·구도가 비슷해도 허용하며, 시각적 유사성 자체로 거절하지 않는다. 같은 캐릭터 외형은 유지하되 각 이미지가 해당 장의 내용을 설명해야 한다. 저장된 이미지는 해당 프로젝트에만 보관하고 재사용 풀로 운영하지 않는다. 재개·검토에서는 이미 저장된 각 배치의 이미지를 유지하며 다시 생성할 필요가 없다.
- **훅·CTA 문구:** 강조 제목은 UPPERCASE, Oswald Bold 700, 110~140px로 작성한다. 이 범위에서 레이아웃이 허용하는 한 최대한 크게 한다. 기본색은 검정(#000000), 강조색은 빨강(#ED1C24)이며 연속된 구절 한 곳에만 사용할 수 있다. 빨강을 띄엄띄엄 여러 구간에 사용하지 않는다. 보조 문구는 페이지당 최대 한 개이며 Inter, 35px, 연회색(#B0B5BE)으로 고정한다. 보조 문구는 없어도 되며 줄바꿈해도 한 문구다. 별도 라벨을 추가해 개수 제한을 피하지 않는다. LIFTCODE 뱃지는 문구 개수에서 제외하고 아래 고정 사양을 따른다. 문구 개수·스타일은 현재 지침과 시각 검토로 확인하며 코드로 강제하지 않는다.
- **이미지 우선:** 이미지가 먼저 눈에 들어오도록 크게 배치한다. 이미지 프레임이나 원본 일부가 슬라이드 밖으로 나가도 된다. 실제로 내보낸 슬라이드 안에서 핵심 자세·동작·비교 대상이 명확하면 허용한다. 프레임 전체를 안에 넣으려고 이미지를 작게 줄이지 않는다. 운동을 이해하는 데 필요한 부위·기구 연결·동작 차이는 잘리지 않아야 한다.
- **텍스트 크기:** 1080px 너비의 슬라이드 기준으로 일반 텍스트는 최소 35px로 한다. 이는 하한이며 모든 문구를 같은 크기로 맞추라는 뜻이 아니다. 아래 고정 LIFTCODE 뱃지만 25px 예외를 적용한다. 글자가 많으면 정보를 나누거나 문구를 정리하며, 최소 크기 아래로 줄이지 않는다.
- **서체:** Oswald는 훅·CTA 페이지에서만 사용할 수 있다. 본문 페이지는 제목·소제목·본문·수치·뱃지를 포함해 Inter만 사용한다. 훅·CTA에서도 모든 문구를 Oswald로 쓸 필요는 없으며 보조 설명은 Inter를 사용할 수 있다.
- **내용과 편집:** 길이보다 각 내용의 역할과 필요성을 기준으로 작성한다. 이해·비교·판단·실행에 필요한 설명은 충분히 담고, 같은 의미의 반복·새 정보를 더하지 않는 문장·이번 내용과 관계없는 부연은 제거한다. 주의사항·이유·조건·팁은 필요할 때 포함하는 예시이며 페이지마다 채워야 하는 항목이 아니다. 중요한 정보나 조건을 생략해 문장·줄 수를 줄이지 않는다. 필요한 내용에 맞춰 위계·묶음·장 수를 조정하며, 원본 배치에 맞추려고 내용을 억지로 줄이거나 늘리지 않는다.
- **타이포 위계:** 먼저 각 문구의 역할과 중요도를 정하고, 서로 다른 위계가 한눈에 구분되게 한다. 보조 라벨·제목·설명은 역할의 예시이며, 모든 페이지를 세 단계로 한정하거나 세 역할을 억지로 채우지 않는다. 크기·굵기(Bold)·줄바꿈·행간·정렬·주변 여백을 함께 설계해 무엇을 먼저 읽고 무엇이 이를 보충하는지 명확히 한다. 크기 차이만으로 위계를 해결하려 하지 않으며, 같은 역할에는 일관된 표현을 쓴다. 보조 문구가 핵심과 시선을 경쟁하지 않게 하고, 실제 슬라이드에서 읽는 순서와 묶음이 즉시 드러나는지 확인한다.
- **간격과 그룹:** 텍스트·인물·기구·도형·뱃지를 하나의 구성으로 보고 서로의 간격을 함께 정한다. 관계가 가까운 내용은 묶되, 각 요소가 분리되어 읽힐 여유를 남긴다. 묶음 내부 간격은 서로 다른 묶음 사이 간격보다 작게 하고, 같은 관계의 간격과 정렬을 페이지마다 유지한다. 간격은 프레임 경계가 아니라 실제 보이는 글자와 피사체 윤곽을 기준으로 판단한다. 이미지의 투명 영역에 글자를 배치할 수 있지만, 피사체와 가까워 붙어 보이거나 읽는 흐름을 방해하면 텍스트와 이미지의 위치·크기·묶음을 함께 조정한다. 하단 설명과 뱃지도 독립적으로 놓지 않고 전체 여백 안에서 분리한다. 프레임끼리 겹치지 않거나 좌표가 같다는 이유만으로 배치가 정돈됐다고 판단하지 않는다.
- **읽는 흐름:** 텍스트를 화면 곳곳에 독립적으로 흩어 놓지 않는다. 내용의 관계와 전개에 맞는 읽기 순서를 정하고, 설명은 관련 대상 가까이에 둔다. 여백은 묶음을 구분하고 핵심을 강조하는 데 사용하며, 빈 공간을 채우려고 중복 제목·추상적 라벨·장식 문구를 추가하지 않는다. 본문은 의미 단위로 줄을 바꾸고, 불필요하게 좁은 상자로 짧은 줄을 여러 개 만들지 않는다.
- **LIFTCODE 뱃지:** 모든 페이지의 하단 왼쪽에 배치한다. 배경은 검은색(#000000), 문구는 LIFTCODE, 서체는 Inter, 글자 크기는 25px, 굵기는 700, 글자색은 흰색(#FFFFFF)으로 고정한다. 너비는 슬라이드 너비의 17.9%, 높이는 슬라이드 높이의 4.6%, 모서리 반경은 99px다. 페이지마다 같은 하단·왼쪽 여백을 유지한다. 뱃지 글자는 일반 텍스트 최소 35px 규칙의 예외이며, 과거 게시글의 큰 뱃지를 따라 확대하지 않는다. 이미지 뒤에 가려지거나 슬라이드 밖으로 잘리지 않아야 한다.

## 4. 전체 결과를 검토하고 저장을 확인한다

도구의 성공 응답만으로 완료를 판단하지 않는다.

- **시각:** 모든 페이지를 실제 미리보기 이미지로 확인한다. 페이지별 이미지 수·이미지 우선 배치·최소 글자 크기·서체·텍스트 위계·하단 왼쪽 뱃지를 점검한다. 시각 검증은 원본 배치와 비교하지 않고 현재 내용에 맞게 조정한다. 최종 슬라이드 경계 안의 화면으로 판단하며 의도적인 이미지 넘침은 오류로 취급하지 않는다. 텍스트 잘림·겹침, 핵심 자세의 손실, 낮은 대비는 수정한다.
- **내용:** 필수 정보와 전개 순서, 훅과 본문의 일치, 주장과 실제 확인 내용의 일치, 이전 게시글 내용의 잔존 여부를 확인한다.
- **언어:** 모든 슬라이드와 제목·캡션·해시태그의 문법, 자연스러움, 반복, 용어와 메시지의 일관성을 확인한다.
- **메타데이터:** [공통 메타데이터 기준](content-metadata.md)에 따라 최종 소재·메시지·포맷을 프로젝트에 저장한다. 제작 완료를 게시 완료로 등록하지 않는다.
- **완료 보고:** 편집한 결과가 저장됐는지 확인하고 프로젝트 링크를 제공한다. 참고한 과거 게시글·지정 레퍼런스와 조사 출처를 남기며, 누락 자산이나 확인하지 못한 부분이 있으면 명시한다.
