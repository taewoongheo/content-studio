# Content Studio

로컬에서 슬라이드를 편집하고 PNG ZIP으로 내보내는 시각 편집기입니다. 콘텐츠 기획·생성은 외부에서 진행하며, 앱은 Codex CLI를 실행하거나 AI 채팅을 제공하지 않습니다.

## 사용

```sh
pnpm install
pnpm exec playwright install chromium
pnpm dev
```

http://127.0.0.1:3000 에서 ‘편집기 열기’ 또는 상단 `+`를 누르면 새 편집기 시작과 기존 프로젝트 선택을 제공합니다. 새 편집기는 4:5 (1080 × 1350), 6장의 빈 문서로 시작합니다. 구성·언어 설정 화면은 없습니다. 화면 비율은 편집기 상단에서, 슬라이드 수는 추가·삭제로 변경합니다. 저장된 프로젝트도 대시보드에서 바로 불러올 수 있습니다.

## 편집

- 텍스트·이미지·도형·배경을 직접 편집합니다.
- Element 정의를 여러 장에서 공유하며, 선택한 장에만 위치·스타일을 적용할 수 있습니다.
- 슬라이드와 레이어 순서를 드래그로 변경합니다.
- 이미지를 캔버스에 드롭하거나 이미지 에셋에서 선택합니다.
- 프로젝트 저장에는 시각 문서와 사용 이미지가 포함됩니다. 대화·제안·AI 쓰레드는 없습니다.
- ZIP 내보내기는 프로젝트를 자동 저장하고 슬라이드별 PNG를 생성합니다.

## 프로젝트 탭

대시보드와 에디터 상단의 탭 목록은 서버에 열린 작업을 표시합니다. 같은 저장 프로젝트를 선택하면 기존 탭으로 이동하고, 닫았다 다시 열면 새로운 탭 ID를 발급합니다. 저장되지 않은 열린 작업도 새 탭의 프로젝트 선택 목록에 표시합니다. 탭 전환 시 입력 중인 텍스트와 배경색을 먼저 반영하며, 프로젝트별 슬라이드·요소 선택, 가이드와 잘린 영역 표시 설정을 복원합니다. 대시보드로 이동해도 탭은 유지합니다.

탭의 `X`는 메모리의 실제 내용과 DB 저장본을 비교합니다. 미저장 변경이 있으면 **저장 후 종료 / 저장하지 않고 종료 / 취소**를 선택합니다. 변경 없는 빈 임시 탭은 DB에 만들지 않고 바로 종료합니다. 종료하면 서버의 문서·되돌리기 이력·구독을 해제하며, 저장 실패나 revision 충돌이면 탭을 유지하고 오류를 표시합니다. 탭 닫기는 저장된 프로젝트나 공용 이미지를 삭제하지 않습니다. 브라우저 새로고침·창 닫기는 서버 탭을 닫지 않습니다. 서버 재시작 시 열린 탭과 되돌리기 이력은 초기화되고 저장 프로젝트를 다시 열 수 있습니다.

탭 이름은 더블 클릭, F2 또는 연필 버튼으로 바꿀 수 있으며 프로젝트 이름과 함께 변경됩니다. 저장된 프로젝트는 이름만 DB에 갱신하고 편집 중인 본문은 저장하지 않습니다. 임시 탭의 이름 변경은 DB에 새 프로젝트를 만들지 않습니다. `+`는 마지막 탭 바로 뒤에 놓습니다. 에디터의 캔버스 높이는 사용 영역의 90%이며 페이지 선택과 옵션은 캔버스 아래에 표시합니다. 저장 목록과 에디터 헤더의 삭제 버튼은 확인 후 저장본과 열린 탭을 함께 삭제합니다. 공용 이미지 에셋은 유지합니다.

MCP 생성·복제·명시적 열기는 탭을 추가하며 현재 브라우저 화면을 강제로 바꾸지 않습니다. MCP에는 탭 닫기 도구를 제공하지 않습니다. 닫힌 작업의 편집은 실패하며, 다시 열린 작업에 이전 탭 ID를 사용하는 요청도 거부합니다. 앱의 탭 닫기는 외부 Codex 에이전트 자체를 중단하지 않습니다.

탭 목록은 여러 브라우저 창이 공유하지만 현재 선택한 탭은 창마다 독립적입니다. 다른 창에서 현재 탭을 닫으면 해당 에디터를 해제하고 대시보드를 표시합니다. 목록 연결이 복구되면 서버의 최신 전체 목록을 다시 받습니다.

## Codex MCP 연결

앱 서버는 `/mcp`에서 로컬 Streamable HTTP MCP 연결을 제공합니다. Codex의 `~/.codex/config.toml`에 등록하고 Codex를 재시작하세요. 앱 서버도 실행되어 있어야 합니다.

`pnpm dev`와 `pnpm start`는 서버를 `127.0.0.1`에만 바인딩합니다. 이 네트워크 경계가 로컬 전용 접근을 보장합니다. Host/Origin 검사는 접속자 인증이 아니므로 외부 인터페이스로 바인딩하거나 역방향 프록시로 노출하지 마세요. 외부 접근을 지원하려면 별도 인증이 필요합니다.

```toml
[mcp_servers.content_studio]
url = "http://127.0.0.1:3000/mcp"
```

- `list_projects`, `open_project`, `read_project`: 저장 프로젝트와 미저장 작업 조회·열기·전체 JSON 읽기
- `create_project`: 원본 ID가 있으면 현재 작업을 복제하고, 없으면 빈 작업 생성. 결과의 URL로 편집기를 엽니다.
- `edit_project`: 명령 배열을 한 번에 적용하고 한 단계로 되돌릴 수 있습니다. `expectedRevision`과 `expectedTabId`에는 최근 읽기·쓰기 응답의 revision과 tabId를 전달합니다.
- `undo_project`: 직전 편집을 취소합니다. 현재 `expectedTabId`와 `expectedRevision`을 전달합니다.
- `preview_slide`: 기존 편집기·내보내기 렌더러로 PNG 이미지를 반환합니다. 미리보기에는 Playwright Chromium이 필요하며, 동시 요청은 프로세스 전체에서 한 번에 하나씩 렌더링합니다.

“이 URL의 프로젝트를 기준으로 가슴 루틴을 새로 만들어줘”라고 요청하면 Codex가 `?job=`의 ID를 `sourceProjectId`로 전달합니다. 원본 없이 요청하면 기본 4:5, 6장의 빈 프로젝트에서 시작합니다. 같은 ID의 미저장 작업이 있으면 저장본보다 우선합니다. 원본 ID를 잘못 지정하면 오류가 발생합니다.

저장된 프로젝트의 열기 버튼 옆과 에디터 헤더의 ‘제작 요청 복사’는 기준 프로젝트 ID와 복제 지시가 포함된 요청문을 클립보드에 복사합니다. Codex에 붙여넣고 새 주제를 덧붙이세요. 주제가 없으면 먼저 질문하도록 요청문에 안내합니다.

에디터는 슬라이드 경계 밖의 요소를 기본적으로 잘라 표시합니다. 상단 ‘잘린 영역 표시’를 켜면 바깥 부분도 볼 수 있습니다. 이 옵션은 편집 화면에만 적용됩니다.

스타일 변경의 `scope: "common"`은 공유 기본값을 바꾸고 변경한 속성의 개별 덮어쓰기를 해제합니다. `scope: "local"`은 해당 장의 배치만 바꿉니다. 좌표는 슬라이드 크기에 대한 비율이고 글자 크기는 px입니다. 요소 정의를 생성한 뒤 각 장에 배치하며, 텍스트 내용과 이미지 ID는 배치의 `value`에 있습니다.

이미지는 Codex가 같은 컴퓨터에서 직접 선택하고 `edit_project`의 명령에 절대 경로를 전달합니다. 이미지 요소를 먼저 생성·배치한 뒤 같은 묶음에서 이 명령을 사용할 수도 있습니다.

```json
{
  "projectId": "작업 ID",
  "expectedRevision": 0,
  "expectedTabId": "현재 열린 탭 ID",
  "commands": [{
    "type": "set_local_image",
    "slideId": "slide-1",
    "placementId": "이미지 배치 ID",
    "localPath": "/absolute/path/exercise.png"
  }]
}
```

앱 서버가 파일을 읽고 PNG/JPG/WebP 검증과 등록 후 문서에 적용합니다. 최대 크기는 10MB입니다. 실패한 묶음은 문서를 바꾸지 않으며 신규 이미지 등록도 롤백합니다. 되돌리기는 문서 배치를 복구하고 등록된 이미지는 유지합니다.

앱은 Codex를 실행하거나 AI 채팅을 제공하지 않습니다. MCP는 같은 로컬 서버 프로세스의 편집 상태와 되돌리기 기록을 사용합니다. `create_project`, `edit_project`, `undo_project`는 최신 문서와 사용 이미지를 DB에 저장한 뒤 성공을 반환합니다. 저장 실패 시 문서·revision·되돌리기 이력과 신규 이미지 등록을 복구하고 오류를 반환합니다. 읽기·열기·미리보기는 자동 저장하지 않습니다. 앱에서 수동 편집한 내용은 저장 버튼·내보내기 또는 탭 닫기의 ‘저장 후 종료’ 선택으로 저장합니다. 저장된 프로젝트 목록과 에디터의 저장 표시는 저장 알림으로 갱신됩니다. 서버 재시작 후 저장된 프로젝트를 열어 최신 문서를 복구할 수 있지만, 되돌리기 이력은 메모리에만 유지되므로 재시작 시 초기화됩니다. 서버를 여러 프로세스로 실행하거나 서버리스로 배포하는 구성은 지원 범위에 포함하지 않습니다.

## 콘텐츠 글꼴

고딕과 고정폭은 실제 로드한 Geist / Geist Mono를 사용합니다. 영문 훅용으로 `bebas-neue`, `anton`, `oswald`, `barlow-condensed`를 선택할 수 있습니다. Bebas Neue와 Anton은 400 단일 굵기이고, Oswald는 200–700, Barlow Condensed는 100–900을 제공합니다. 글자 굵기 선택창은 각 폰트가 제공하는 굵기를 표시하며, MCP에도 같은 fontFamily 값을 사용할 수 있습니다. 렌더링 전에 필요한 폰트와 굵기를 로드하므로 에디터·미리보기·내보내기에 동일하게 적용됩니다. 한글 글리프는 해당 영문 폰트에 없으므로 시스템 폰트로 대체됩니다.

## 텍스트 부분 색상

텍스트 요소를 선택한 뒤 ‘내용’에서 글자를 선택하고 ‘선택 색상 적용’을 누릅니다. 선택 구간만 해제하거나 모든 부분 색상을 해제할 수 있습니다. 부분 색상은 해당 장의 텍스트 배치에 저장하며, 지정하지 않은 글자는 기존 기본 색상을 따릅니다. 텍스트를 편집하면 남은 구간 위치를 보정하고, 한 색상 안에서 교체한 내용은 그 색상을 이어받습니다.

MCP의 `edit_project`에서도 사용할 수 있습니다.

```json
{
  "type": "set_slot_value",
  "slideId": "slide-1",
  "placementId": "title-1",
  "value": "BUILD CHEST",
  "textColors": [{ "start": 6, "end": 11, "color": "#FF0000" }]
}
```

내용을 유지하고 색상만 바꾸려면 `set_text_colors`에 같은 `textColors`를 전달합니다. 배열은 전체 부분 색상을 교체하며 `[]`는 모두 해제합니다. 구간은 UTF-16 인덱스, 끝 제외 방식이고, 정렬된 비중첩 구간과 6자리 HEX 색상을 사용합니다. 이모지나 결합 문자 중간을 자르는 구간은 거부합니다. `set_slot_value`에서 `textColors`를 생략하면 기존 색상을 새 내용에 맞춰 보정합니다. 복제·되돌리기·저장·PNG 내보내기에도 반영됩니다.

## 데이터

SQLite 기본 위치는 프로젝트 상위 워크스페이스의 `content-studio.sqlite`입니다. 이미지 바이트와 메타데이터, 저장 프로젝트를 SQLite에서 관리합니다. 편집 중인 문서는 앱 서버 메모리에 유지합니다.

## 검증

```sh
pnpm test
pnpm exec tsc --noEmit
pnpm lint
pnpm build
pnpm test:mcp
pnpm test:mcp --production
```

`test:mcp`는 임시 DB와 별도 포트에서 서버를 실행하고 실제 MCP HTTP 클라이언트 및 브라우저로 편집·화면 반영·복제·이미지·미리보기·되돌리기·자동 저장·목록 갱신·탭 전환 및 입력 flush·두 창의 탭 종료·이전 탭 요청 거부와 실제 서버 재시작 후 문서/이미지 복구를 검증합니다. `--production`은 먼저 빌드한 결과를 검증합니다. 사용자의 Codex 설정과 기존 DB는 변경하지 않습니다.
